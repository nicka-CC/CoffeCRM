# Описание страниц CoffeCRM

## Страница: Главная (Dashboard)

### 1. Обзор и назначение

**Dashboard** — это центральная информационная панель системы CoffeCRM, служащая отправной точкой для всех пользователей, вошедших в систему. Её основная задача — предоставление комплексного и наглядного обзора ключевых бизнес-метрик и операционных показателей в режиме реального времени. Страница спроектирована таким образом, чтобы дать пользователю (вероятнее всего, администратору или менеджеру) возможность быстро оценить текущее состояние дел, выявить тенденции, аномалии и принять оперативные решения.

Стилистически страница выполнена в современном, минималистичном дизайне с использованием карточек, графиков и списков, что способствует лёгкому восприятию большого объёма данных. Основной акцент сделан на визуализацию, позволяющую не "читать" цифры, а "видеть" их в контексте.

**Ключевые цели страницы:**
*   **Мониторинг:** Отслеживание финансовых и операционных показателей (выручка, количество заказов, средний чек).
*   **Аналитика:** Предоставление инструментов для базового анализа данных, таких как график продаж и статистика по самым популярным товарам.
*   **Операционное управление:** Обеспечение быстрого доступа к основным действиям в системе через панель быстрых ссылок.

### 2. Техническая реализация (Frontend)

Страница реализована как React-компонент с использованием фреймворка Next.js. Код располагается в файле `frontend/coffecrm/app/page.tsx`.

**Ключевые технологии и библиотеки:**
*   **React:** Основа для построения пользовательского интерфейса.
*   **Next.js:** Фреймворк для React, предоставляющий маршрутизацию (в данном случае, это главная страница, доступная по маршруту `/`) и другие возможности.
*   **Material-UI (MUI):** Библиотека UI-компонентов, которая используется для создания всех визуальных элементов: сетки (`Grid`), карточек (`Card`, `Paper`), кнопок (`Button`), иконок, типографики (`Typography`) и элементов форм (`FormControl`, `Select`).
*   **Recharts:** Библиотека для создания декларативных графиков в React. На странице используется для построения линейного графика продаж (`LineChart`).
*   **Хуки React:**
    *   `useState`: Для управления состоянием компонента (выбранный период `period`, статус загрузки `loading`, ошибки `error`, полученные данные `dashboardData`).
    *   `useEffect`: Для выполнения сайд-эффектов, в данном случае — для асинхронного запроса данных с сервера при монтировании компонента или изменении выбранного периода.
*   **Маршрутизация:** `useRouter` из `next/navigation` для навигации к другим разделам приложения (например, при клике на кнопки быстрых действий).

### 3. Источник данных (Backend API)

Страница получает все необходимые данные через единственный API-эндпоинт: `GET /dashboard`.

*   **URL:** `{API_BASE_URL}/dashboard?period={period}`
*   **Метод:** `GET`
*   **Параметры запроса:**
    *   `period`: Строка, определяющая временной интервал для агрегации данных. Принимает значения:
        *   `'day'` (данные за текущий день)
        *   `'week'` (данные за последнюю неделю)
        *   `'month'` (данные за последний месяц)
*   **Аутентификация:** Запрос требует аутентификации. В заголовки запроса добавляется токен (например, `Authorization: Bearer <token>`) с помощью вспомогательной функции `withAuthHeaders()`.
*   **Структура ответа (JSON):**
    ```json
    {
      "kpis": {
        "revenue": 150000,
        "ordersCount": 85,
        "averageCheck": 1764.7,
        "newCustomers": 12
      },
      "salesChart": [
        { "label": "00:00", "revenue": 10000, "orders": 5 },
        { "label": "03:00", "revenue": 15000, "orders": 8 },
        // ... другие временные точки
      ],
      "topProducts": [
        { "productId": "prod-1", "name": "Эспрессо", "quantity": 150, "revenue": 15000 },
        { "productId": "prod-2", "name": "Круассан", "quantity": 120, "revenue": 12000 },
        // ... другие товары
      ],
      "branchStats": [
        // ... статистика по филиалам (не используется в текущей версии UI)
      ],
      "statusDistribution": [
        // ... распределение заказов по статусам (не используется)
      ],
      "quickLinks": [
        // ... ссылки для быстрых действий (не используются, логика захардкожена)
      ]
    }
    ```

### 4. Структура и компоненты страницы

Страница логически разделена на несколько блоков, расположенных в общем `Layout` компоненте, который обеспечивает наличие бокового меню навигации и общего стиля приложения.

#### 4.1. Заголовок и фильтр периода
*   **Заголовок:** "Dashboard" и подзаголовок "Главная панель управления". Реализован с помощью компонента `<Typography>` из MUI.
*   **Фильтр:** Расположен в правой части шапки контентной области.
    *   **Компонент:** `<FormControl>` с `<Select>` внутри.
    *   **Функциональность:** Позволяет пользователю выбрать один из трёх периодов: "День", "Неделя", "Месяц". При изменении значения в `Select` обновляется состояние `period`, что вызывает повторный запрос данных с сервера через `useEffect`.

#### 4.2. Блок KPI (Key Performance Indicators)
Этот блок представляет собой сетку (`Grid`) из четырёх карточек (`Paper`), каждая из которых отображает один ключевой показатель.

*   **Карточка "Выручка" (`revenue`):**
    *   **Визуальное оформление:** Светло-голубой фон (`#f0f9ff`).
    *   **Данные:** Отображает общую выручку за выбранный период. Значение форматируется как валюта (например, "150 000 ₽") с помощью утилиты `formatCurrency`.
    *   **Иконка:** `ShoppingCart` (хотя в коде не отображается, логически подходит).

*   **Карточка "Заказов" (`ordersCount`):**
    *   **Визуальное оформление:** Светло-жёлтый фон (`#fff3cd`).
    *   **Данные:** Показывает общее количество заказов за период.
    *   **Иконка:** `TrendingUp`.

*   **Карточка "Средний чек" (`averageCheck`):**
    *   **Визуальное оформление:** Светло-зелёный фон (`#d1fae5`).
    *   **Данные:** Отображает среднюю стоимость одного заказа (Выручка / Количество заказов). Также форматируется как валюта.
    *   **Иконка:** `Coffee`.

*   **Карточка "Новых клиентов" (`newCustomers`):**
    *   **Визуальное оформление:** Светло-фиолетовый фон (`#e0e7ff`).
    *   **Данные:** Показывает количество новых клиентов, зарегистрированных за выбранный период.
    *   **Иконка:** `People`.

#### 4.3. Блок с графиками
Этот блок содержит два основных элемента: график продаж и список самых популярных товаров.

*   **График продаж (`salesChart`):**
    *   **Компонент:** `<LineChart>` из библиотеки Recharts, обёрнутый в `<ResponsiveContainer>` для адаптивности.
    *   **Назначение:** Визуализирует динамику выручки и количества заказов в течение выбранного периода.
    *   **Оси:**
        *   `XAxis`: Метки времени или даты (`label` из данных `salesChart`).
        *   `YAxis`: Числовые значения для выручки и заказов.
    *   **Линии:**
        *   **Выручка (`revenue`):** Линия фиолетового цвета (`#6366f1`).
        *   **Заказы (`orders`):** Линия зелёного цвета (`#10b981`).
    *   **Интерактивность:**
        *   `Tooltip`: При наведении на точку графика появляется всплывающая подсказка с точными значениями выручки и заказов для данной временной метки.
        *   `Legend`: Внизу графика отображается легенда, поясняющая, какая линия что означает.

*   **Список "ТОП товаров" (`topProducts`):**
    *   **Назначение:** Показывает 5 самых продаваемых товаров за выбранный период.
    *   **Структура:** Вертикальный список (`Stack`), где каждый элемент представляет один товар.
    *   **Элемент списка:**
        *   **Аватар:** Кружок с порядковым номером товара в топе (1, 2, 3...).
        *   **Название товара:** Отображается жирным шрифтом.
        *   **Дополнительная информация:** Количество проданных штук и общая выручка по этому товару.

### 5. Пользовательские сценарии и состояния

#### 5.1. Успешная загрузка
1.  Пользователь открывает главную страницу.
2.  Компонент отправляет запрос на `GET /dashboard?period=day`.
3.  На время загрузки отображается компонент `<CircularProgress />` (индикатор загрузки).
4.  Сервер отвечает с кодом 200 и данными в формате JSON.
5.  Данные сохраняются в состоянии `dashboardData`.
6.  Страница отрисовывает все компоненты (KPI, график, топ товаров) с полученными данными.

#### 5.2. Ошибка при загрузке
1.  Пользователь открывает главную страницу.
2.  Запрос на `GET /dashboard` завершается с ошибкой (например, сервер недоступен, ошибка 500, или ответ не в формате JSON).
3.  Ошибка перехватывается в блоке `catch`.
4.  Сообщение об ошибке сохраняется в состоянии `error`.
5.  Вместо данных на странице отображается компонент `<Alert severity="error">` с текстом ошибки (например, "Не удалось загрузить данные Dashboard").

#### 5.3. Изменение периода
1.  Пользователь кликает на выпадающий список "Период".
2.  Выбирает новое значение, например, "Неделя".
3.  Срабатывает событие `onChange`, которое обновляет состояние `period` на `'week'`.
4.  `useEffect` отслеживает изменение `period` и инициирует новый запрос на `GET /dashboard?period=week`.
5.  Далее процесс повторяется, как при успешной загрузке, и все компоненты на странице обновляются с новыми данными.

#### 5.4. Быстрые действия (гипотетический сценарий)
Хоть в текущей реализации данные `quickLinks` не используются, функция `handleQuickAction` присутствует. Предполагаемый сценарий:
1.  На странице есть кнопки, например, "Создать заказ", "Добавить товар".
2.  Пользователь нажимает кнопку "Создать заказ".
3.  Вызывается `handleQuickAction('createOrder')`.
4.  Функция находит соответствующий путь (`/orders/new`) в `actionMap`.
5.  С помощью `router.push()` пользователь перенаправляется на страницу создания нового заказа.

## Страница: Аналитика (Analytics)

### 1. Обзор и назначение

Страница "Аналитика" представляет собой мощный инструмент для углубленного анализа данных о продажах и клиентах в системе CoffeCRM. В отличие от Dashboard, который даёт общий срез текущей ситуации, эта страница предназначена для более детального изучения исторических данных, выявления закономерностей и подготовки отчётности.

Она позволяет пользователям не просто просматривать данные, но и взаимодействовать с ними: фильтровать по различным периодам, включая произвольные, и экспортировать результаты в популярных форматах (Excel, PDF) для дальнейшей обработки или предоставления руководству.

**Ключевые цели страницы:**
*   **Глубокий анализ:** Предоставление детализированных графиков по различным аспектам бизнеса (динамика продаж, эффективность филиалов, поведение клиентов).
*   **Гибкая фильтрация:** Возможность анализировать данные за стандартные (неделя, месяц, квартал) и произвольные периоды времени.
*   **Отчётность:** Генерация и экспорт формализованных отчётов по ключевым срезам данных.
*   **Выявление инсайтов:** Помощь в обнаружении наиболее прибыльных клиентов, популярных товаров, эффективных филиалов и пиковых часов нагрузки.

### 2. Техническая реализация (Frontend)

Страница находится в файле `frontend/coffecrm/app/analytics/page.tsx`.

**Ключевые технологии и библиотеки:**
*   **React/Next.js:** Основа приложения.
*   **Material-UI (MUI):** Широко используется для всех элементов интерфейса, включая `Paper` для карточек, `Grid` для разметки, `Button`, `Select`, `TextField` для интерактивных элементов, и иконки.
*   **Recharts:** Библиотека является ядром страницы и используется для создания всех четырёх аналитических графиков: `LineChart`, `BarChart` и `PieChart`.
*   **Хуки React:** `useState` и `useEffect` для управления состоянием (фильтры, данные, загрузка) и жизненным циклом компонента.

### 3. Источники данных и экспорт (Backend API)

Страница взаимодействует с двумя основными эндпоинтами.

#### 3.1. Получение данных для аналитики
*   **URL:** `{API_BASE_URL}/analytics`
*   **Метод:** `GET`
*   **Параметры запроса:**
    *   `period`: `'week'`, `'month'`, `'quarter'`, `'custom'`.
    *   `from` (опционально): Дата начала периода в формате `YYYY-MM-DD`. Используется, если `period` равен `'custom'`.
    *   `to` (опционально): Дата конца периода в формате `YYYY-MM-DD`. Используется, если `period` равен `'custom'`.
*   **Структура ответа (JSON):**
    ```json
    {
      "salesDynamics": [
        { "date": "2023-10-01", "revenue": 25000, "orders": 15 },
        // ...
      ],
      "topProducts": [ /* ... */ ],
      "topCustomers": [
        { "customerId": "cust-1", "name": "Иван Петров", "phone": "+7...", "revenue": 50000 },
        // ...
      ],
      "branchSales": [
        { "branchId": "br-1", "name": "Филиал на Ленина", "revenue": 120000 },
        // ...
      ],
      "peakHours": [
        { "hour": 9, "orders": 25 },
        { "hour": 18, "orders": 40 },
        // ...
      ]
    }
    ```

#### 3.2. Экспорт отчётов
*   **URL:** `{API_BASE_URL}/analytics/export`
*   **Метод:** `GET`
*   **Параметры запроса:**
    *   `dataset`: Определяет, какой набор данных экспортировать. Принимает значения: `'sales'`, `'branches'`, `'products'`, `'customers'`.
    *   `format`: Формат файла. Принимает значения: `'excel'`, `'pdf'`.
    *   `period`, `from`, `to`: Аналогичны запросу на получение данных.
*   **Ответ:** Файл в виде `blob`, который затем на клиенте преобразуется в ссылку для скачивания. Имя файла генерируется динамически и включает тип отчёта и текущую дату/время.

### 4. Структура и компоненты страницы

#### 4.1. Панель управления (Заголовок и действия)
*   **Заголовок:** "Аналитика".
*   **Кнопка "Обновить":** Позволяет пользователю вручную перезапросить данные с сервера.
*   **Меню "Экспорт отчета":** Выпадающий список (`Select`), сгруппированный по форматам (Excel, PDF). Каждый пункт меню инициирует скачивание соответствующего отчёта.

#### 4.2. Панель фильтров
Вынесена в отдельную карточку (`Paper`) для визуального отделения.
*   **Выбор периода:** `Select` для выбора стандартных периодов ('Неделя', 'Месяц', 'Квартал').
*   **Выбор произвольного периода:** Если выбран период 'Произвольный', динамически появляются два поля `TextField` с типом `date` для выбора начальной и конечной даты.

#### 4.3. Сетка с аналитическими виджетами
Основное пространство страницы занимает сетка (`Grid`) 2x2, в каждой ячейке которой находится карточка (`Paper`) с одним из графиков.

*   **1. Динамика продаж (`salesDynamics`):**
    *   **Тип:** Линейный график (`LineChart`).
    *   **Назначение:** Показывает изменение количества заказов и выручки с течением времени.
    *   **Особенность:** Использует две оси Y (`YAxis`) для корректного отображения двух разных по масштабу величин (штуки и деньги).
    *   **Интерактивность:** Подробные всплывающие подсказки (`RechartsTooltip`) при наведении.

*   **2. ТОП клиентов (`topCustomers`):**
    *   **Тип:** Горизонтальная столбчатая диаграмма (`BarChart` с `layout="vertical"`).
    *   **Назначение:** Ранжирует клиентов по общей сумме их заказов (выручке).
    *   **Визуализация:** Каждый столбец — это клиент. Длина столбца пропорциональна выручке. Имена клиентов отображаются на оси Y.
    *   **Дополнительно:** В заголовке виджета есть иконка для быстрого экспорта именно этого отчёта в Excel.

*   **3. Продажи по филиалам (`branchSales`):**
    *   **Тип:** Кольцевая диаграмма (`PieChart` с `innerRadius`).
    *   **Назначение:** Демонстрирует вклад каждого филиала в общую выручку.
    *   **Визуализация:** Каждый сектор представляет филиал, его размер пропорционален доле выручки. В центре диаграммы — пустое пространство. Легенда справа показывает процентное соотношение.
    *   **Интерактивность:** При наведении на сектор во всплывающей подсказке отображается точная сумма выручки.

*   **4. Пиковые часы заказов (`peakHours`):**
    *   **Тип:** Вертикальная столбчатая диаграмма (`BarChart`).
    *   **Назначение:** Показывает распределение количества заказов по часам суток (от 0 до 23).
    *   **Визуализация:** Ось X — часы, ось Y — количество заказов. Столбцы, соответствующие "пиковым" часам (например, обеденное время и вечер), окрашены в более насыщенный цвет для акцента.
    *   **Дополнительно:** Под графиком есть поясняющая надпись о цветовом кодировании.

### 5. Пользовательские сценарии

*   **Базовый анализ:** Пользователь открывает страницу, видит данные за месяц (по умолчанию). Он изучает общую динамику, смотрит, какие клиенты и филиалы приносят больше всего денег.
*   **Сравнительный анализ:** Пользователь выбирает период "Квартал", чтобы оценить показатели в более долгосрочной перспективе. Затем он может выбрать предыдущий квартал через "Произвольный" период и сравнить результаты.
*   **Подготовка отчёта:** Менеджеру нужен отчёт по продажам для совещания. Он открывает страницу, выбирает нужный период, затем в меню "Экспорт отчета" выбирает "Отчет по продажам (PDF)" и скачивает готовый файл.
