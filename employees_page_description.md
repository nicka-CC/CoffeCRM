# Описание страницы "Сотрудники" (`/employees`)

## 1. Обзор и назначение

Страница "Сотрудники" является ключевым элементом системы управления персоналом (HRM) внутри CRM. Она позволяет менеджерам и администраторам централизованно управлять профилями сотрудников, назначать их на должности и филиалы, а также, что наиболее важно, отслеживать их производительность через систему ключевых показателей эффективности (KPI).

**Ключевые цели страницы:**

*   **Управление персоналом:** Предоставить полный набор инструментов для CRUD-операций над профилями сотрудников.
*   **Организационная структура:** Связывать сотрудников с существующими пользователями системы и назначать их на определенные филиалы.
*   **Мониторинг производительности:** Реализовать функционал для просмотра и анализа KPI каждого сотрудника за различные периоды времени.
*   **Эффективный поиск:** Обеспечить возможность быстрого поиска и фильтрации сотрудников для удобства администрирования.
*   **Контроль доступа:** Гарантировать, что только уполномоченные лица могут вносить изменения в данные о сотрудниках.

## 2. Структура и компоненты

Страница объединяет в себе несколько мощных компонентов для реализации всего спектра задач по управлению персоналом.

### 2.1. Основной компонент: `EmployeesPage.tsx`

Это главный компонент страницы, который служит точкой входа и управляет взаимодействием всех дочерних элементов.

**Путь:** `frontend/coffecrm/app/employees/page.tsx`

**Ключевые обязанности:**

*   **Состояние (State Management):**
    *   `employees: Employee[]`: Список сотрудников для отображения на текущей странице.
    *   `loading`, `error`: Стандартные флаги состояния для асинхронных операций.
    *   **Фильтрация и пагинация:**
        *   `filters`: Объект, содержащий параметры фильтрации (`search`, `branchId`).
        *   `page`, `rowsPerPage`, `total`: Состояния для управления серверной пагинацией.
    *   **Диалоговые окна:**
        *   `formOpen`, `kpiDialogOpen`: Флаги для управления видимостью модальных окон.
        *   `selectedEmployee: Employee | null`: Хранит данные сотрудника, выбранного для редактирования или просмотра KPI.

*   **Взаимодействие с API:**
    *   **`fetchEmployees`:** Загружает список сотрудников с бэкенда (`GET /employees`), используя параметры из состояния `filters` и пагинации. Вся логика фильтрации и пагинации выполняется на сервере.
    *   **`handleDeleteEmployee`:** Отправляет `DELETE` запрос на `/employees/:id` после подтверждения пользователя.

*   **Обработчики событий:**
    *   `handleAddEmployee`, `handleEditEmployee`: Открывают модальное окно `EmployeeForm`.
    *   `handleViewKPI`: Открывает модальное окно `EmployeeKPIDialog`.
    *   `handleFormClose`, `handleKpiDialogClose`: Закрывают соответствующие модальные окна.
    *   `handleFormSuccess`: Инициирует перезагрузку списка сотрудников после успешного сохранения.

*   **Визуальная структура (Layout):**
    *   Панель действий с кнопками "Обновить" и "Добавить сотрудника".
    *   Панель фильтров с полем для поиска.
    *   Основной контент с `EmployeeTable` и `TablePagination`.

### 2.2. Компонент таблицы: `EmployeeTable.tsx`

Отображает список сотрудников со всей ключевой информацией.

**Путь:** `frontend/coffecrm/components/Employees/EmployeeTable.tsx`

**Ключевые особенности:**

*   **Колонки:**
    *   **Сотрудник:** Аватар, ФИО и email.
    *   **Должность:** Должность сотрудника.
    *   **Роль:** Системная роль пользователя (например, "Администратор"), отображаемая цветным `Chip` для быстрой идентификации.
    *   **Филиал:** Название и город филиала, к которому привязан сотрудник.
    *   **Зарплата:** Оклад, отформатированный как валюта.
    *   **KPI:** Кнопка для вызова диалогового окна с показателями эффективности.
    *   **Действия:** Кнопки для редактирования и удаления профиля.
*   **Контроль доступа:** Кнопки редактирования и удаления деактивируются на основе прав, полученных из хука `usePermissions`. **Примечание:** в кнопке удаления обнаружена потенциальная ошибка `canEditResource('products', '1')`, где ресурс должен быть `'employee'`.

### 2.3. Компонент формы: `EmployeeForm.tsx`

Модальная форма для создания и редактирования профилей сотрудников.

**Путь:** `frontend/coffecrm/components/Employees/EmployeeForm.tsx`

**Особенности:**

*   **Агрегация данных:** При открытии форма асинхронно загружает списки всех пользователей (`/user/all`) и всех филиалов (`/branches`) с помощью `Promise.all`. Это необходимо для заполнения выпадающих списков.
*   **Режимы работы:**
    *   **Создание:** Позволяет выбрать существующего пользователя из списка и создать для него профиль сотрудника, указав должность, зарплату и филиал.
    *   **Редактирование:** Поле выбора пользователя заблокировано, так как связь "профиль сотрудника — пользователь" считается постоянной.
*   **Поля формы:**
    *   `userId`: Выпадающий список пользователей (обязательное поле).
    *   `position`: Должность (обязательное поле).
    *   `salary`: Зарплата.
    *   `branchId`: Выпадающий список филиалов.
*   **Отправка данных:** Собирает `payload` и отправляет `POST` (для создания) или `PATCH` (для редактирования) запрос на эндпоинт `/employees`.

### 2.4. Диалоговое окно KPI: `EmployeeKPIDialog.tsx`

Уникальный для этого раздела компонент, представляющий собой мини-дашборд производительности сотрудника.

**Путь:** `frontend/coffecrm/components/Employees/EmployeeKPIDialog.tsx`

**Особенности:**

*   **Динамическая загрузка KPI:** При открытии или при смене периода в фильтре компонент отправляет запрос на `GET /employees/:id/kpi?period=...`, где `period` может быть 'week', 'month' или 'quarter'.
*   **Фильтр по периоду:** Выпадающий список позволяет пользователю легко переключаться между отчетами за неделю, месяц или квартал.
*   **Визуализация данных:**
    *   **Сводка:** Верхний блок с `Paper` отображает три ключевых суммарных показателя: общее количество заказов, общая выручка и средний чек.
    *   **Таблица метрик:** Вторая часть отображает таблицу с более гранулярными, специфичными метриками, каждая из которых имеет название, значение и дату.
*   **UX:** Компонент имеет собственные состояния `loading` и `error` для обеспечения плавной работы и информирования пользователя в процессе загрузки данных KPI.

## 3. Поток данных и взаимодействие с API

1.  **Загрузка страницы:** `EmployeesPage` отправляет `GET /employees` с параметрами пагинации.
2.  **Просмотр KPI:**
    *   Пользователь нажимает иконку `AssessmentIcon` в строке сотрудника.
    *   `EmployeeTable` вызывает `onViewKPI(employee)`.
    *   `EmployeesPage` открывает `EmployeeKPIDialog`, передавая в него `selectedEmployee`.
    *   `EmployeeKPIDialog` отправляет `GET /employees/:id/kpi?period=month` (по умолчанию).
    *   API возвращает данные KPI, которые отображаются в диалоговом окне.
    *   Пользователь меняет период на "Неделя". `EmployeeKPIDialog` отправляет новый запрос `GET /employees/:id/kpi?period=week`.
3.  **Создание сотрудника:**
    *   Пользователь нажимает "Добавить сотрудника".
    *   `EmployeeForm` открывается и отправляет `Promise.all([GET /branches, GET /user/all])`.
    *   После загрузки данных пользователь выбирает пользователя и филиал, заполняет поля.
    *   `EmployeeForm` отправляет `POST /employees`.
    *   После успеха `onSuccess` инициирует `fetchEmployees`, и новый сотрудник появляется в таблице.

## 4. Визуальный дизайн и UX

*   **Фокус на данных:** Дизайн страницы прагматичен и сфокусирован на представлении данных в наиболее читаемом виде (таблицы, цветные чипы, четко разделенные блоки).
*   **Вложенная функциональность:** Реализация просмотра KPI в модальном окне является хорошим примером "прогрессивного раскрытия", позволяя не перегружать основной интерфейс, но предоставляя мощные инструменты по запросу.
*   **Эффективность рабочего процесса:** Асинхронная загрузка данных для форм (`Promise.all`) и серверная пагинация/фильтрация в основной таблице обеспечивают быстрый и отзывчивый интерфейс.
