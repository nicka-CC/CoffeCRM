
# Описание главной страницы (Dashboard)

## 1. Общее назначение

Главная страница (`/`) представляет собой "Dashboard" или панель управления, которая предоставляет пользователю сводную информацию о ключевых показателях эффективности (KPI) бизнеса за определённый период. Страница предназначена для быстрого обзора текущего состояния дел, отслеживания динамики продаж и выявления наиболее популярных товаров.

Это стартовый экран приложения после авторизации, который служит отправной точкой для дальнейшей работы с системой.

## 2. Структура страницы

Страница построена с использованием библиотеки Material-UI и состоит из следующих основных блоков, расположенных внутри общего компонента `Layout`:

1.  **Заголовок страницы**.
2.  **Фильтр по периоду**.
3.  **Блок с ключевыми показателями (KPI)**.
4.  **Блок с графиками**:
    *   График продаж.
    *   Список ТОП-продаваемых товаров.

## 3. Компоненты и их функциональность

### 3.1. Компонент `Layout`

Это внешний компонент-обертка, который обеспечивает единообразный внешний вид для всех страниц приложения. На главной странице он используется для отображения:

*   **Основного заголовка (Title):** "Dashboard"
*   **Подзаголовка (Subtitle):** "Главная панель управления"

### 3.2. Состояния загрузки и ошибок

Страница обрабатывает три состояния при получении данных с сервера:

*   **Загрузка (`loading`):** Пока данные с бэкенда загружаются, в центре экрана отображается анимированный индикатор загрузки (`CircularProgress`). Это предотвращает отображение пустой или неполной страницы и информирует пользователя об идущем процессе.
*   **Ошибка (`error`):** Если при запросе данных происходит ошибка (например, сервер недоступен или вернул ошибку), на странице отображается компонент `Alert` с красным фоном и сообщением об ошибке. Текст по умолчанию: "Ошибка загрузки данных".
*   **Успешная загрузка:** Когда данные получены, отображается основное содержимое страницы.

### 3.3. Фильтр по периоду

*   **Компонент:** `FormControl` с `Select` (выезжающее меню) из Material-UI.
*   **Расположение:** В верхней части страницы, справа от заголовка "Статистика".
*   **Функциональность:** Позволяет пользователю выбрать временной интервал для отображения статистики.
*   **Опции:**
    *   `День` (значение: `day`)
    *   `Неделя` (значение: `week`)
    *   `Месяц` (значение: `month`)
*   **Поведение:** При выборе нового значения из списка состояние `period` обновляется, что инициирует повторный запрос данных с сервера (`fetchDashboard`) с новым параметром периода. Страница переходит в состояние загрузки и затем отображает обновленные данные. По умолчанию выбран период "День".

### 3.4. Блок ключевых показателей (KPI)

*   **Компонент:** `Grid` (сетка) из четырех колонок, каждая из которых содержит компонент `Paper` (карточка).
*   **Назначение:** Отображение четырех основных бизнес-метрик в наглядном виде. Каждая карточка имеет свой цвет фона для визуального разделения.

#### 3.4.1. Карточка "Выручка"
*   **Компонент:** `Paper`
*   **Отображаемые данные:** `kpis.revenue`
*   **Форматирование:** Сумма форматируется с помощью функции `formatCurrency` (например, `10 000 ₽`).
*   **Стиль:** Крупный синий шрифт для суммы, подпись "Выручка" под ней.

#### 3.4.2. Карточка "Заказов"
*   **Компонент:** `Paper`
*   **Отображаемые данные:** `kpis.ordersCount`
*   **Форматирование:** Отображается как целое число.
*   **Стиль:** Крупный оранжевый шрифт для числа, подпись "Заказов" под ним.

#### 3.4.3. Карточка "Средний чек"
*   **Компонент:** `Paper`
*   **Отображаемые данные:** `kpis.averageCheck`
*   **Форматирование:** Сумма форматируется с помощью `formatCurrency`.
*   **Стиль:** Крупный зеленый шрифт для суммы, подпись "Средний чек" под ней.

#### 3.4.4. Карточка "Новых клиентов"
*   **Компонент:** `Paper`
*   **Отображаемые данные:** `kpis.newCustomers`
*   **Форматирование:** Отображается как целое число.
*   **Стиль:** Крупный фиолетовый шрифт для числа, подпись "Новых клиентов" под ней.

### 3.5. Блок с графиками

Представляет собой сетку (`Grid`) из двух колонок. Левая колонка (широкая) содержит график продаж, правая (узкая) — список лучших товаров.

#### 3.5.1. График продаж
*   **Компонент:** `LineChart` из библиотеки Recharts, обернутый в `ResponsiveContainer` для адаптивности.
*   **Заголовок блока:** "График продаж".
*   **Назначение:** Визуализация динамики выручки и количества заказов за выбранный период.
*   **Оси:**
    *   **Ось X (горизонтальная):** Метки времени (`label` из `salesChart` данных), например, часы для дня или дни для недели/месяца.
    *   **Ось Y (вертикальная):** Числовые значения для выручки и заказов.
*   **Линии:**
    *   **"Выручка" (`revenue`):** Фиолетовая линия (`#6366f1`).
    *   **"Заказы" (`orders`):** Зеленая линия (`#10b981`).
*   **Интерактивность:**
    *   **Подсказка (`Tooltip`):** При наведении на точку на графике появляется всплывающая подсказка с точными значениями выручки и заказов для данной метки времени.
    *   **Легенда (`Legend`):** Под графиком отображается легенда, поясняющая, какая линия что означает.
*   **Сетка (`CartesianGrid`):** На фоне графика отображается пунктирная сетка для удобства восприятия значений.

#### 3.5.2. ТОП товаров
*   **Компонент:** `Stack` (вертикальный список), содержащий до 5 дочерних элементов.
*   **Заголовок блока:** "ТОП товаров".
*   **Назначение:** Отображение списка самых продаваемых товаров за выбранный период.
*   **Структура элемента списка:** Каждый элемент представляет один товар и содержит:
    *   **Порядковый номер:** Компонент `Avatar` с синим фоном и номером от 1 до 5.
    *   **Название товара:** `product.name`.
    *   **Статистика продаж:** Строка вида `{количество} шт. • {сумма выручки}` (например, "15 шт. • 3 500 ₽").
*   **Данные:** Используются первые 5 элементов из массива `topProducts`.

## 4. Логика получения данных (Data Fetching)

*   **Endpoint:** Данные запрашиваются с `API_BASE_URL/dashboard`.
*   **Метод:** `GET`
*   **Параметры:**
    *   `period`: `day`, `week` или `month`.
*   **Авторизация:** Запрос отправляется с заголовками авторизации, которые добавляются функцией `withAuthHeaders`.
*   **Жизненный цикл:**
    1.  Первичная загрузка данных происходит при монтировании компонента (`useEffect` с пустым массивом зависимостей).
    2.  Повторная загрузка происходит каждый раз при изменении состояния `period` (`useEffect` с зависимостью `[period]`).
    3.  Перед каждым запросом устанавливается `setLoading(true)`, а после его завершения (успешного или нет) — `setLoading(false)`.

## 5. Навигация (Routing)

*   **Инструмент:** `useRouter` из `next/navigation`.
*   **Реализация:** На странице присутствует функция `handleQuickAction`, которая должна была бы перенаправлять пользователя на страницы создания новых сущностей (заказа, продукта и т.д.).
*   **Важное замечание:** Несмотря на наличие этой функции в коде, **ни один видимый элемент на странице её не вызывает**. Таким образом, с точки зрения пользователя, на главной странице нет кнопок для быстрой навигации.
