# Описание страницы "Клиенты" (`/customers`)

## 1. Обзор и назначение

Страница "Клиенты" — это ядро CRM-функциональности приложения. Она предоставляет мощный и многофункциональный интерфейс для управления клиентской базой. В отличие от более простых страниц, таких как "Категории", эта страница включает в себя расширенные возможности: сводную аналитику, поиск, фильтрацию и пагинацию, что необходимо для эффективной работы с большими объемами данных.

**Ключевые цели страницы:**

*   **Полный обзор клиентской базы:** Предоставить наглядное представление всех клиентов с ключевыми финансовыми и статусными метриками.
*   **Сегментация и анализ:** Дать возможность быстро фильтровать и находить клиентов по различным критериям (поиск по имени/контактам, VIP-статус).
*   **Сводная аналитика:** Отображать на дашборде ключевые показатели, такие как общее количество клиентов, число VIP-клиентов, суммарная выручка и накопленные бонусы.
*   **Управление жизненным циклом клиента:** Обеспечить полный цикл CRUD-операций, а также предоставить доступ к связанным данным (история заказов, бонусы).
*   **Масштабируемость:** Эффективно работать с большим количеством записей благодаря серверной пагинации.

## 2. Структура и компоненты

Страница имеет сложную структуру, включающую несколько информационных блоков и компонентов для взаимодействия с данными.

### 2.1. Основной компонент: `CustomersPage.tsx`

Центральный компонент, управляющий всей логикой страницы.

**Путь:** `frontend/coffecrm/app/customers/page.tsx`

**Ключевые обязанности:**

*   **Состояние (State Management):**
    *   `customers: Customer[]`: Список клиентов для текущей страницы.
    *   `loading: boolean`, `error: string | null`: Стандартные состояния для отслеживания статуса API-запросов.
    *   **Фильтрация и поиск:**
        *   `search: string`: Строка для полнотекстового поиска по клиентам.
        *   `vipFilter: string`: Фильтр по VIP-статусу ('', 'true', 'false').
    *   **Пагинация:**
        *   `page: number`: Номер текущей страницы (начиная с 1).
        *   `rowsPerPage: number`: Количество записей на одной странице.
        *   `total: number`: Общее количество клиентов в базе данных (для расчета общего числа страниц).
    *   **Форма:**
        *   `formOpen: boolean`: Управляет видимостью модального окна `CustomerForm`.
        *   `selectedCustomer: Customer | null`: Данные клиента для редактирования.

*   **Взаимодействие с API:**
    *   **`fetchCustomers`:** Основная функция для загрузки данных. Она динамически конструирует URL с помощью утилиты `buildUrl`, добавляя параметры `search`, `vipStatus`, `page` и `limit`. Это означает, что вся фильтрация, поиск и пагинация выполняются на стороне сервера, что критически важно для производительности.
    *   `useEffect`: Хук следит за изменениями `search`, `vipFilter`, `page`, `rowsPerPage` и автоматически вызывает `fetchCustomers` при любом изменении, обеспечивая реактивность интерфейса.

*   **Обработчики событий:**
    *   `handleAddCustomer`, `handleEdit`: Управляют открытием формы `CustomerForm` в режимах создания и редактирования.
    *   `handleFormClose`, `handleFormSuccess`: Закрывают форму и инициируют обновление данных.
    *   `handleViewHistory`, `handleViewBonuses`: Перенаправляют пользователя на страницы истории заказов и бонусов клиента соответственно.
    *   Обработчики пагинации: `onPageChange` и `onRowsPerPageChange` обновляют состояние `page` и `rowsPerPage`.

*   **Визуальная структура (Layout):**
    *   **Сводный дашборд:** Четыре `Paper`-компонента вверху страницы для отображения ключевых метрик.
    *   **Панель фильтров:** `Paper`-компонент с полями для поиска и фильтрации.
    *   **Таблица:** Отображает `CustomerTable` с данными.
    *   **Пагинация:** Компонент `TablePagination` под таблицей.

### 2.2. Компонент таблицы: `CustomerTable.tsx`

Отображает детализированную информацию о клиентах в табличном виде.

**Путь:** `frontend/coffecrm/components/Customers/CustomerTable.tsx`

**Ключевые особенности:**

*   **Колонки:** Таблица предоставляет богатый набор данных по каждому клиенту:
    *   **Клиент:** Аватар, ФИО и email.
    *   **Статус:** `Chip`'ы для VIP-статуса и персональной скидки.
    *   **Финансовые показатели:** Количество заказов, общая сумма трат, средний чек.
    *   **Бонусы:** Текущий баланс бонусных баллов.
    *   **Действия:** Группа `IconButton`'ов для различных операций.
*   **Действия (Actions):**
    *   **Просмотр (`VisibilityIcon`):** Для перехода на страницу с детальной информацией о клиенте (в коде `handleView` пока выводит в консоль).
    *   **История заказов (`HistoryIcon`):** Переход на страницу истории заказов клиента.
    *   **Бонусы (`CardGiftcardIcon`):** Переход на страницу истории начисления и списания бонусов.
    *   **Редактировать (`EditIcon`):** Вызывает `onEdit` для открытия формы редактирования.
*   **Контроль доступа:**
    *   Все кнопки действий в таблице защищены проверкой `canEditResource('products', '1')`. **Примечание:** Здесь, вероятно, допущена ошибка (copy-paste), так как ресурс должен быть `'customer'`, а не `'products'`. Это потенциальная уязвимость или баг, который следует исправить.

### 2.3. Компонент формы: `CustomerForm.tsx`

Сложная модальная форма для создания и редактирования профиля клиента.

**Путь:** `frontend/coffecrm/components/Customers/CustomerForm.tsx`

**Режимы работы:**

*   **Создание:** Форма содержит выпадающий список "Пользователь", который позволяет привязать создаваемый профиль клиента к уже существующему в системе пользователю. Для этого форма загружает список всех пользователей с эндпоинта `/user/all`.
*   **Редактирование:** Выпадающий список "Пользователь" скрыт, так как предполагается, что привязка пользователя к профилю клиента не меняется.

**Поля формы:**

*   `userId`: ID пользователя (только при создании).
*   `bonus`, `discountPercent`: Числовые поля для управления программой лояльности.
*   `vipStatus`: Переключатель `Switch`.
*   `source`: Текстовое поле для указания источника привлечения.
*   `birthday`: Поле для ввода даты рождения.
*   `tags`: Текстовое поле для тегов (ввод через запятую).
*   `notes`: Многострочное текстовое поле для заметок.

**Логика работы:**

*   **Загрузка пользователей:** В режиме создания инициируется загрузка списка пользователей для привязки.
*   **Обработка данных:** Перед отправкой на сервер строка с тегами (`form.tags`) преобразуется в массив строк.
*   **Контроль доступа:** Поля и кнопка отправки заблокированы, если у пользователя нет прав на создание (`canCreateResource`) или редактирование (`canEditResource`).

## 3. Поток данных и взаимодействие с API

1.  **Загрузка страницы:** `CustomersPage` отправляет `GET` запрос на `/customers` с параметрами пагинации по умолчанию (`page=1`, `limit=20`).
2.  **Поиск/Фильтрация:** Пользователь вводит текст в поле поиска. `state.search` обновляется. `useEffect` срабатывает и отправляет новый `GET` запрос на `/customers` с параметром `search=...`. API на сервере фильтрует результаты.
3.  **Пагинация:** Пользователь нажимает на кнопку "следующая страница". `state.page` обновляется. `useEffect` отправляет `GET` запрос на `/customers` с новым `page=...`.
4.  **Создание клиента:**
    *   Пользователь нажимает "Добавить клиента".
    *   `CustomerForm` открывается и загружает список пользователей (`GET /user/all`).
    *   Пользователь выбирает пользователя, заполняет поля и нажимает "Добавить".
    *   `CustomerForm` отправляет `POST` запрос на `/customers` с данными.
    *   После успеха `onSuccess` инициирует `fetchCustomers`, и новый клиент появляется в таблице (вероятно, на первой странице).
5.  **Редактирование клиента:**
    *   Пользователь нажимает иконку "Редактировать".
    *   `CustomerForm` открывается с данными выбранного клиента.
    *   Пользователь изменяет данные и нажимает "Сохранить".
    *   `CustomerForm` отправляет `PATCH` запрос на `/customers/:id`.
    *   После успеха `fetchCustomers` обновляет данные в таблице.

## 4. Визуальный дизайн и UX

*   **Информационная плотность:** Страница эффективно использует пространство, предоставляя как сводную аналитику, так и детализированную таблицу.
*   **Быстрый доступ к действиям:** Наличие панели фильтров и кнопок действий непосредственно над таблицей ускоряет работу пользователя.
*   **Обратная связь:** Использование `CircularProgress` при загрузке и `Alert` при ошибках четко информирует пользователя о состоянии системы.
*   **Эффективность:** Серверная пагинация и фильтрация являются ключевыми UX-решениями, обеспечивающими высокую производительность при работе с большой клиентской базой.
