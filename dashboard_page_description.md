# Подробное описание страницы "Dashboard" (`/`)

## 1. Введение

Страница "Dashboard" является главной ("домашней") страницей CRM-системы после авторизации пользователя. Она служит центральной информационной панелью, предоставляя оперативный обзор ключевых показателей эффективности (KPI) и общей активности бизнеса. Цель этой страницы — дать пользователю, будь то менеджер или администратор, быстрое и ясное представление о текущем состоянии дел, позволяя отслеживать основные метрики и выявлять тенденции без необходимости углубляться в детализированные отчеты.

Страница спроектирована как современный, отзывчивый и интуитивно понятный интерфейс, который агрегирует и визуализирует наиболее важные данные из различных модулей системы: заказы, клиенты, товары и финансы.

## 2. Архитектура и расположение

-   **Путь в приложении:** `/`
-   **Расположение файла:** `frontend/coffecrm/app/page.tsx`
-   **Технологический стек:**
    -   **Фреймворк:** Next.js (с использованием App Router)
    -   **Язык:** TypeScript
    -   **UI-библиотека:** Material-UI (MUI)
    -   **Библиотека для графиков:** Recharts
    -   **Стилизация:** Встроенные в MUI `sx` пропсы и кастомные стили.

## 3. Общая структура страницы

Страница, как и все остальные страницы в приложении, встроена в единый компонент `Layout`, который обеспечивает консистентность внешнего вида и навигации.

Структура страницы делится на три основных слоя:

1.  **Компонент `Layout` (оболочка):**
    *   **Боковая панель (`Sidebar`):** Расположена слева, содержит ссылки для навигации по всем разделам CRM (Дашборд, Пользователи, Филиалы, Товары и т.д.). Панель может быть свернута до иконок для экономии места.
    *   **Верхняя панель (`AppBar`):** Горизонтальная панель вверху экрана. В ней находится меню пользователя с возможностью перейти в профиль (`My account`) или выйти из системы (`Logout`).
    *   **Основная область контента:** Пространство, где рендерится непосредственно содержимое страницы "Dashboard".

2.  **Содержимое страницы "Dashboard":**
    *   **Заголовок:** Отображает название страницы "Dashboard" и подзаголовок "Главная панель управления".
    *   **Панель управления:** Содержит интерактивные элементы, такие как фильтр по периоду.
    *   **Сетка с KPI:** Блок с ключевыми показателями.
    *   **Сетка с графиками и списками:** Блок с визуализациями данных.

## 4. Поток данных (Data Flow)

Страница является клиентским компонентом (`'use client';`), что означает, что она рендерится и является интерактивной в браузере пользователя.

1.  **Инициализация:** При загрузке страницы компонент инициализирует свое состояние: `loading` в `true`, `error` в `null`, и `period` по умолчанию в `'day'`.
2.  **Запрос данных:**
    *   Срабатывает `useEffect`, который вызывает асинхронную функцию `fetchDashboard`.
    *   `fetchDashboard` отправляет GET-запрос на API-эндпоинт: `${API_BASE_URL}/dashboard?period=${period}`. Например, при выборе периода "Неделя", URL будет `.../dashboard?period=week`.
    *   Запрос отправляется с заголовком авторизации (`Authorization: Bearer <token>`), который формируется функцией `withAuthHeaders()`.
3.  **Обработка ответа:**
    *   **Успешный ответ (`response.ok`):**
        *   JSON-тело ответа парсится.
        *   Полученные данные сохраняются в состояние `dashboardData`.
        *   Состояние `loading` устанавливается в `false`, а `error` в `null`.
        *   Компонент перерисовывается, отображая данные.
    *   **Ошибка (`!response.ok` или сетевая ошибка):**
        *   Генерируется и обрабатывается исключение.
        *   Текст ошибки сохраняется в состояние `error`.
        *   `loading` устанавливается в `false`.
        *   Компонент перерисовывается, отображая компонент `<Alert>` с сообщением об ошибке.
4.  **Интерактивность (смена периода):**
    *   Пользователь выбирает новый период в выпадающем списке (`Select`).
    *   Событие `onChange` обновляет состояние `period`.
    *   Обновление `period` триггерит повторный вызов `useEffect` и, следовательно, `fetchDashboard`, запуская цикл запроса данных заново.

**Структура получаемых данных (`dashboardData`):**

```typescript
interface DashboardData {
  kpis: {
    revenue: number;        // Выручка
    ordersCount: number;    // Количество заказов
    averageCheck: number;   // Средний чек
    newCustomers: number;   // Количество новых клиентов
  };
  salesChart: {
    label: string;          // Метка для оси X (например, дата или час)
    revenue: number;        // Выручка за этот период
    orders: number;         // Количество заказов за этот период
  }[];
  topProducts: {
    productId: string;
    name: string;           // Название товара
    quantity: number;       // Проданное количество
    revenue: number;        // Выручка от продажи этого товара
  }[];
  // Эти поля есть в коде, но не используются в UI:
  branchStats: any;
  statusDistribution: any;
  quickLinks: any;
}
```

## 5. Детальный разбор UI-компонентов

### 5.1. Фильтр по периоду

-   **Компонент:** `FormControl` с `InputLabel` и `Select` от Material-UI.
-   **Назначение:** Позволяет пользователю выбрать временной интервал для отображения статистики.
-   **Опции:**
    -   `День` (value: `"day"`)
    -   `Неделя` (value: `"week"`)
    -   `Месяц` (value: `"month"`)
-   **Поведение:** При выборе опции обновляется состояние `period`, что инициирует новый запрос к API.

### 5.2. Карточки KPI (KPI Cards)

-   **Контейнер:** `Grid` (контейнер) с четырьмя `Grid` (элементами), каждый из которых содержит компонент `Paper`.
-   **Назначение:** Отображение четырех важнейших метрик в легко читаемом формате. Каждая карточка имеет свой цветовой акцент для визуального разделения.
-   **Компоненты:**
    1.  **Выручка:**
        -   Цвет фона: `#f0f9ff` (светло-голубой).
        -   Значение: `kpis.revenue`, форматируется функцией `formatCurrency()` (например, в "150 000 ₽").
        -   Текст значения имеет основной цвет темы (`primary.main`).
    2.  **Заказов:**
        -   Цвет фона: `#fff3cd` (светло-желтый).
        -   Значение: `kpis.ordersCount`.
        -   Текст значения имеет "предупреждающий" цвет темы (`warning.main`).
    3.  **Средний чек:**
        -   Цвет фона: `#d1fae5` (светло-зеленый).
        -   Значение: `kpis.averageCheck`, также форматируется `formatCurrency()`.
        -   Текст значения имеет "успешный" цвет темы (`success.main`).
    4.  **Новых клиентов:**
        -   Цвет фона: `#e0e7ff` (светло-фиолетовый).
        -   Значение: `kpis.newCustomers`.
        -   Текст значения имеет "информационный" цвет темы (`info.main`).

### 5.3. График продаж (Sales Chart)

-   **Контейнер:** `Grid` элемент, занимающий 8 из 12 колонок на средних и больших экранах, внутри которого находится `Paper`.
-   **Назначение:** Визуализация динамики продаж и заказов за выбранный период.
-   **Компонент:** `LineChart` из библиотеки `Recharts`, обернутый в `ResponsiveContainer` для автоматического подстраивания под размер контейнера.
-   **Элементы графика:**
    -   **`CartesianGrid`:** Рисует пунктирную сетку на фоне.
    -   **`XAxis`:** Горизонтальная ось, в качестве меток (`dataKey`) использует поле `label` из массива `salesChart`.
    -   **`YAxis`:** Вертикальная ось для значений.
    -   **`Tooltip`:** Всплывающая подсказка, которая появляется при наведении на точки графика и показывает точные значения.
    -   **`Legend`:** Легенда, объясняющая, какая линия что означает ("Выручка", "Заказы").
    -   **`Line` (Выручка):**
        -   Тип: `monotone` (сглаженная линия).
        -   Данные: `dataKey="revenue"`.
        -   Цвет: `#6366f1` (фиолетовый).
    -   **`Line` (Заказы):**
        -   Тип: `monotone`.
        -   Данные: `dataKey="orders"`.
        -   Цвет: `#10b981` (зеленый).

### 5.4. ТОП товаров (Top Products)

-   **Контейнер:** `Grid` элемент, занимающий 4 из 12 колонок, внутри `Paper`.
-   **Назначение:** Отображение списка самых продаваемых товаров за выбранный период.
-   **Компоненты:** `Stack` для вертикального расположения списка товаров.
-   **Отображение:**
    -   Берутся первые 5 элементов из массива `topProducts`.
    -   Каждый товар отображается в `Box` с использованием Flexbox для выравнивания.
    -   **`Avatar`:** Показывает порядковый номер товара в топе (1, 2, 3...).
    -   **`Typography` (название):** Жирным шрифтом выводится `product.name`.
    -   **`Typography` (детали):** Мелким шрифтом (caption) отображается количество проданных штук (`product.quantity`) и выручка от них (`product.revenue`), отформатированная `formatCurrency()`.

## 6. Состояния загрузки и ошибок

-   **Состояние загрузки (`loading === true`):**
    -   Пока данные загружаются, на месте контента страницы отображается компонент `CircularProgress` (стандартный спиннер из Material-UI), расположенный по центру. Это обеспечивает хороший пользовательский опыт, информируя, что процесс идет.
-   **Состояние ошибки (`error` содержит строку):**
    -   Если произошла ошибка при запросе данных, вместо контента отображается компонент `<Alert severity="error">`.
    -   Внутри алерта выводится сообщение об ошибке из состояния `error`, либо стандартное "Ошибка загрузки данных", если `error` пуст.

## 7. Неиспользуемая функциональность

В коде компонента присутствует функция `handleQuickAction` и деструктуризация полей `branchStats`, `statusDistribution`, `quickLinks` из `dashboardData`. Эти элементы не используются в текущей JSX-разметке. Это может означать:

-   **Устаревший код:** Функциональность была удалена из UI, но осталась в логике.
-   **Незавершенная разработка:** Планировалось добавить блок "Быстрые действия" (Quick Links) или дополнительные графики, но работа еще не закончена. Например, `quickLinks` могли бы рендерить кнопки для быстрого создания заказа или товара.

Этот факт важен для понимания потенциальных направлений развития страницы.
