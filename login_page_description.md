
# Подробное описание страницы авторизации (LoginPage)

## 1. Введение

Этот документ содержит исчерпывающее описание страницы авторизации (`LoginPage`) фронтенд-приложения CoffeCRM. Страница предназначена для аутентификации пользователей в системе. Она предоставляет пользовательский интерфейс для ввода учетных данных (электронной почты и пароля) и выполняет запрос к бэкенду для проверки этих данных. В случае успешной аутентификации пользователь перенаправляется на другую страницу, в противном случае — получает сообщение об ошибке.

Основная цель страницы — обеспечить безопасный и интуитивно понятный способ входа в систему для зарегистрированных пользователей.

## 2. Файловая структура

Логика и структура страницы авторизации полностью инкапсулированы в одном файле, что соответствует конвенциям фреймворка Next.js для маршрутизации на основе файловой системы:

-   `frontend/coffecrm/app/login/page.tsx`

Этот файл является точкой входа для роута `/login` и содержит все необходимые компоненты, стили и логику.

## 3. Обзор компонента `LoginPage`

`LoginPage` — это функциональный React-компонент, созданный с использованием "клинского" рендеринга (`'use client'`). Это означает, что компонент будет рендериться на стороне клиента, что необходимо для использования хуков React, таких как `useState` и `useRouter`, и для взаимодействия с пользователем в браузере.

Компонент импортирует необходимые зависимости:

-   `useState` из `react` для управления состоянием.
-   `useRouter` из `next/navigation` для программной навигации.
-   Компоненты из библиотеки Material-UI (`@mui/material`), такие как `Container`, `TextField`, `Button`, `CircularProgress`, для построения пользовательского интерфейса.
-   `LayoutAdmin` - кастомный компонент-обертка, который, вероятно, предоставляет общий макет для административных страниц, включая заголовок страницы.

## 4. Управление состоянием (State Management)

Компонент использует хук `useState` для управления своим внутренним состоянием. Это состояние определяет поведение и отображение UI в зависимости от действий пользователя.

-   `const [email, setEmail] = useState('');`
    -   **Назначение**: Хранит значение, введенное пользователем в поле "Почта".
    -   **Начальное значение**: `''` (пустая строка).
    -   **Использование**: `value` для `TextField` почты и обновляется через `onChange`. Используется в теле запроса к API.

-   `const [password, setPassword] = useState('');`
    -   **Назначение**: Хранит значение, введенное пользователем в поле "Пароль".
    -   **Начальное значение**: `''` (пустая строка).
    -   **Использование**: `value` для `TextField` пароля и обновляется через `onChange`. Используется в теле запроса к API.

-   `const [loading, setLoading] = useState(false);`
    -   **Назначение**: Управляет состоянием загрузки во время выполнения асинхронного запроса на вход.
    -   **Начальное значение**: `false`.
    -   **Использование**: Когда `true`, кнопка "Войти" блокируется, и вместо текста на ней отображается индикатор загрузки (`CircularProgress`). Это предотвращает повторные отправки формы.

-   `const [error, setError] = useState('');`
    -   **Назначение**: Хранит сообщение об ошибке, которое будет показано пользователю в случае неудачной авторизации или сетевой проблемы.
    -   **Начальное значение**: `''` (пустая строка).
    -   **Использование**: Если `error` содержит строку, она отображается под формой в виде красного текста.

## 5. Пользовательский интерфейс (UI) и компоненты

Интерфейс страницы построен с использованием компонентов из библиотеки `@mui/material`, что обеспечивает консистентный и современный внешний вид.

-   **`LayoutAdmin`**:
    -   Это корневой компонент-обертка. Он принимает `title` в качестве пропа (`title="Авторизация"`). Вероятно, он отвечает за отображение общего заголовка страницы и, возможно, навигационной панели или бокового меню, характерных для административной части приложения.

-   **`Container`**:
    -   Оборачивает форму входа.
    -   `maxWidth="sm"`: Ограничивает максимальную ширину контейнера до `small` (стандартное значение в теме Material-UI), что центрирует форму на больших экранах.
    -   Стили: `display: 'flex', flexDirection: 'column', gap: '1rem', minWidth:'500px', marginTop:'20px'`. Эти стили организуют дочерние элементы (поля ввода и кнопку) в вертикальную колонку с отступом (`gap`) в `1rem` между ними. `minWidth` гарантирует, что форма не станет слишком узкой, а `marginTop` добавляет отступ сверху.

-   **`TextField` для почты**:
    -   `label="Почта"`: Отображает плейсхолдер и метку для поля.
    -   `value={email}`: Связывает значение поля с состоянием `email`.
    -   `onChange={(e) => setEmail(e.target.value)}`: Обновляет состояние `email` при каждом изменении в поле ввода.

-   **`TextField` для пароля**:
    -   `label="Пароль"`: Метка для поля.
    -   `type="password"`: Скрывает вводимые символы, заменяя их точками, что является стандартом для полей пароля.
    -   `value={password}`: Связывает значение поля с состоянием `password`.
    -   `onChange={(e) => setPassword(e.target.value)}`: Обновляет состояние `password` при вводе.

-   **`Button`**:
    -   `variant="contained"`: Стиль кнопки с заливкой.
    -   `onClick={handleLogin}`: При нажатии вызывает функцию `handleLogin`, которая инициирует процесс аутентификации.
    -   `disabled={loading}`: Кнопка становится неактивной, когда `loading` равно `true`.
    -   Содержимое кнопки: `{loading ? <CircularProgress size={24} /> : 'Войти'}`. Это условный рендеринг. Если идет загрузка, показывается `CircularProgress` (анимированный индикатор загрузки) размером 24px. В противном случае отображается текст "Войти".

-   **Отображение ошибки**:
    -   `{error && <p style={{ color: 'red' }}>{error}</p>}`: Условный рендеринг. Если состояние `error` не является пустой строкой, под кнопкой отображается параграф (`<p>`) с текстом ошибки красного цвета.

## 6. Логика и взаимодействие с пользователем (`handleLogin`)

Функция `handleLogin` является асинхронной и содержит всю логику процесса аутентификации.

1.  **Начало процесса**:
    -   `setLoading(true);`: Устанавливает состояние загрузки в `true`. UI немедленно реагирует, блокируя кнопку и показывая индикатор загрузки.
    -   `setError('');`: Сбрасывает предыдущие сообщения об ошибках, чтобы пользователь не видел старое сообщение при новой попытке входа.

2.  **API-запрос**:
    -   Используется `fetch` для отправки `POST`-запроса на `http://localhost:7000/auth/login`.
    -   `method: 'POST'`: Указывает HTTP-метод.
    -   `headers: { 'Content-Type': 'application/json' }`: Сообщает серверу, что тело запроса отформатировано в JSON.
    -   `body: JSON.stringify({ identifier: email, password })`: Преобразует объект с `email` (под ключом `identifier`) и `password` в JSON-строку.

3.  **Обработка ответа**:
    -   `const data = await res.json();`: Парсит JSON-ответ от сервера.
    -   **Успешный вход (`res.ok`)**:
        -   `sessionStorage.setItem('access_token', data.access_token);`: Если ответ успешный (HTTP-статус 2xx), токен доступа (`access_token`) из ответа сохраняется в `sessionStorage` браузера. Это позволяет использовать токен для последующих аутентифицированных запросов.
        -   `router.push('/users');`: Пользователь перенаправляется на страницу `/users`. Хук `useRouter` предоставляет эту возможность.
    -   **Неудачный вход**:
        -   `setError(data.message || 'Ошибка авторизации');`: Если сервер вернул ошибку, состояние `error` обновляется сообщением из ответа сервера (`data.message`). Если сообщение отсутствует, используется запасной текст 'Ошибка авторизации'.

4.  **Обработка сетевых ошибок**:
    -   Блок `catch (err)`: Если `fetch` не удался (например, из-за проблем с сетью или недоступности сервера), ошибка логируется в консоль (`console.error(err)`), и в состояние `error` записывается сообщение 'Ошибка сети'.

5.  **Завершение процесса**:
    -   Блок `finally`: Этот блок выполняется всегда, независимо от того, был ли запрос успешным или нет.
    -   `setLoading(false);`: Устанавливает состояние загрузки обратно в `false`, что разблокирует кнопку и убирает индикатор загрузки.

## 7. Взаимодействие с API

-   **Эндпоинт**: `http://localhost:7000/auth/login`
-   **Метод**: `POST`
-   **Заголовки**: `Content-Type: application/json`
-   **Тело запроса (Payload)**:
    ```json
    {
      "identifier": "user@example.com", // Значение из состояния email
      "password": "user_password"      // Значение из состояния password
    }
    ```
-   **Ожидаемый успешный ответ (Response)**:
    ```json
    {
      "access_token": "some.jwt.token"
    }
    ```
-   **Ожидаемый ответ с ошибкой**:
    ```json
    {
      "message": "Invalid credentials" // или другое сообщение об ошибке
    }
    ```

## 8. Аспекты безопасности

-   **Хранение токена**: Токен доступа сохраняется в `sessionStorage`. Это означает, что токен будет доступен только в течение текущей сессии вкладки браузера и будет удален при ее закрытии. Это более безопасно, чем `localStorage`, для хранения сессионных токенов, так как уменьшает окно для XSS-атак, которые могут попытаться украсть токен.
-   **Передача пароля**: Пароль передается в теле POST-запроса. Если используется HTTPS (что является обязательным для продакшн-окружения), тело запроса будет зашифровано, что защищает учетные данные от перехвата.

## 9. Маршрутизация

-   `const router = useRouter();`: Инициализирует хук `useRouter` из `next/navigation`, который предоставляет доступ к объекту маршрутизатора.
-   `router.push('/users');`: Выполняет навигацию на стороне клиента на страницу `/users` после успешного входа. Это происходит без полной перезагрузки страницы, что улучшает пользовательский опыт.
