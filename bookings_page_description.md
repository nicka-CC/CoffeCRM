# Подробное описание страницы "Бронирования" (`/bookings`)

## 1. Введение

Страница "Бронирования" является одним из самых интерактивных и многофункциональных разделов CRM-системы. Она предоставляет полный набор инструментов для управления жизненным циклом бронирований — от их создания до завершения или отмены. Этот модуль критически важен для бизнесов, где требуется предварительная запись клиентов, например, для бронирования столиков в ресторане, записи на мероприятия или встречи.

Страница предлагает два альтернативных режима просмотра данных — классическую таблицу и наглядный календарь, а также мощные средства фильтрации и выполнения быстрых действий.

## 2. Архитектура и расположение

-   **Путь в приложении:** `/bookings`
-   **Расположение основного файла:** `frontend/coffecrm/app/bookings/page.tsx`
-   **Дочерние компоненты:**
    -   `frontend/coffecrm/components/Bookings/BookingTable.tsx`
    -   `frontend/coffecrm/components/Bookings/BookingCalendar.tsx`
    -   `frontend/coffecrm/components/Bookings/BookingForm.tsx` (модальное окно)
    -   `frontend/coffecrm/components/Bookings/BookingDetails.tsx` (модальное окно)
-   **Типы данных:** `frontend/coffecrm/types/bookings.ts`

## 3. Компонентная архитектура

Страница построена по принципу "умного" контейнера и "глупых" презентационных компонентов:

1.  **`BookingsPage` (Контейнер):**
    -   Выполняет всю основную логику: управляет состоянием (фильтры, пагинация, список броней), взаимодействует с API (загрузка, обновление, изменение статуса) и координирует работу дочерних компонентов.
    -   Передает данные и функции-колбэки в дочерние компоненты через пропсы.

2.  **`BookingTable` и `BookingCalendar` (Презентационные):**
    -   Отвечают исключительно за отображение данных, которые они получают от `BookingsPage`.
    -   При взаимодействии с пользователем (например, клик по кнопке "Редактировать") они не выполняют логику, а вызывают колбэк (`onEdit(booking)`), переданный от родителя.

3.  **`BookingForm` и `BookingDetails` (Модальные окна):**
    -   `BookingForm` является более сложным, так как содержит собственную логику управления состоянием формы и загрузки зависимостей (списков клиентов и филиалов). Однако, результат своей работы (успешное сохранение) он также сообщает родителю через колбэк `onSuccess`.
    -   `BookingDetails` — чисто презентационный компонент для отображения деталей, который также вызывает колбэки для выполнения действий.

Такая архитектура делает код более читаемым, переиспользуемым и легким для тестирования.

## 4. Поток данных и жизненный цикл

### 4.1. Загрузка данных

-   При монтировании `BookingsPage` или изменении зависимостей (`filters`, `page`, `rowsPerPage`) срабатывает `useEffect`, вызывающий `fetchBookings`.
-   `fetchBookings` формирует URL с параметрами фильтрации и пагинации (e.g., `/api/bookings?status=PENDING&page=1&limit=20`).
-   Полученный от API массив бронирований и общее количество записей (`total`) сохраняются в состояние, что вызывает перерисовку `BookingTable` или `BookingCalendar`.

### 4.2. Создание/Редактирование

1.  Пользователь нажимает "Создать бронирование" или "Редактировать" в таблице.
2.  `BookingsPage` изменяет состояние `formOpen` на `true` и, в случае редактирования, `selectedBooking` на данные редактируемой брони.
3.  Открывается модальное окно `BookingForm`.
4.  `BookingForm` загружает списки клиентов и филиалов для выпадающих списков.
5.  Пользователь заполняет и отправляет форму.
6.  `BookingForm` отправляет `POST` или `PATCH` запрос к API.
7.  В случае успеха, `BookingForm` вызывает колбэки `onSuccess()` и `onClose()`.
8.  Вызов `onSuccess()` в `BookingsPage` инициирует повторную загрузку данных через `fetchBookings()`, обновляя список на главной странице.

### 4.3. Изменение статуса (Подтверждение/Отмена/Завершение)

1.  Пользователь нажимает на кнопку действия (например, "Подтвердить") в `BookingTable` или `BookingDetails`.
2.  Компонент вызывает соответствующий колбэк в `BookingsPage` (например, `onConfirm(booking.id)`).
3.  Обработчик в `BookingsPage` (например, `handleConfirmBooking`) отправляет `PUT` запрос на специализированный эндпоинт (e.g., `/api/bookings/{id}/confirm`).
4.  В случае успеха, немедленно вызывается `fetchBookings()`, чтобы обновить UI и показать новый статус бронирования.

## 5. Детальный разбор UI и функциональности

### 5.1. Основная страница (`BookingsPage`)

-   **KPI-карточки:** Верхний блок для быстрой оценки ситуации: "Всего бронирований", "Ожидают", "Подтверждено" и общая "Выручка" по завершенным броням.
-   **Переключатель вида (`Tabs`):**
    -   **"Таблица" (`TableChartIcon`):** Отображает компонент `BookingTable`.
    -   **"Календарь" (`CalendarMonthIcon`):** Отображает компонент `BookingCalendar`.
-   **Панель фильтров:** Позволяет гибко настраивать выборку данных по статусу, типу, дате и текстовому поиску по клиенту, телефону или столу.

### 5.2. Таблица бронирований (`BookingTable`)

-   **Отображение:** Классическая таблица со строгим набором колонок.
-   **Статусы:** Статус бронирования выделяется цветом с помощью компонента `Chip` для быстрой визуальной идентификации.
-   **Действия:** Колонки "Действия" содержат иконки для всех возможных операций над бронированием, доступность которых зависит от статуса брони и прав пользователя.

### 5.3. Календарь бронирований (`BookingCalendar`)

-   **Реализация:** Самописный компонент, имитирующий календарь на месяц.
-   **Визуализация:** Бронирования отображаются как небольшие цветные `Chip` внутри ячеек дней. Цвет соответствует статусу.
-   **Интерактивность:** Клик по `Chip` открывает детальный просмотр бронирования (`BookingDetails`).

### 5.4. Форма бронирования (`BookingForm`)

-   **Назначение:** Единый интерфейс для создания и редактирования.
-   **Поля:** Содержит исчерпывающий набор полей, позволяя указать все детали бронирования — от клиента и времени до особых пожеланий, тегов и деталей оплаты.
-   **Удобство:** Автоматически подгружает связанные данные (клиентов, филиалы), избавляя пользователя от необходимости вводить ID вручную.

### 5.5. Детали бронирования (`BookingDetails`)

-   **Назначение:** Представление всей информации о бронировании в удобном для чтения виде.
-   **Структура:** Данные сгруппированы по семантическим блокам: "Информация о бронировании", "Филиал и клиент", "Оплата", "Внутренние заметки" и т.д.
-   **Контекстные действия:** Кнопки действий в футере модального окна меняются в зависимости от статуса бронирования, предлагая пользователю только релевантные на данный момент операции. Например, нельзя "Завершить" бронирование, которое еще не было "Подтверждено".
