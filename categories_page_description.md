# Описание страницы "Категории" (`/categories`)

## 1. Обзор и назначение

Страница "Категории" представляет собой интерфейс для управления классификацией товаров. Категории являются важной частью каталога продукции, позволяя организовывать товары (например, "Кофе", "Десерты", "Напитки") для удобства навигации, учета и анализа продаж. Эта страница предоставляет администраторам и менеджерам все необходимые инструменты для выполнения полного цикла CRUD-операций (создание, чтение, обновление, удаление) над категориями.

**Ключевые цели страницы:**

*   **Централизованное управление:** Предоставить единое место для просмотра и управления всеми категориями товаров в системе.
*   **Структурирование каталога:** Дать возможность создавать, редактировать и удалять категории, тем самым формируя логическую структуру ассортимента.
*   **Визуальное представление:** Отображать категории в наглядном табличном виде с иконками и датами создания.
*   **Контроль доступа:** Обеспечить, чтобы только авторизованные пользователи могли вносить изменения, используя систему разрешений.

## 2. Структура и компоненты

Страница реализована с помощью нескольких специализированных React-компонентов, которые разделяют общую логику и представление.

### 2.1. Основной компонент: `CategoriesPage.tsx`

Это главный компонент, который управляет состоянием страницы и координирует работу дочерних компонентов.

**Путь:** `frontend/coffecrm/app/categories/page.tsx`

**Ключевые обязанности:**

*   **Состояние (State Management):**
    *   `categories: Category[]`: Массив объектов, содержащий полный список категорий, загруженный с сервера.
    *   `loading: boolean`: Флаг для отображения индикатора загрузки (`CircularProgress`) во время запросов к API.
    *   `error: string | null`: Содержит текст ошибки, если запрос завершился неудачно.
    *   `formOpen: boolean`: Управляет видимостью модального окна `CategoryForm`.
    *   `selectedCategory: Category | null`: Хранит данные категории, выбранной для редактирования. Если `null`, форма открывается в режиме создания.

*   **Взаимодействие с API (CRUD):**
    *   **`fetchCategories` (Read):** Асинхронная функция для загрузки списка категорий. Отправляет `GET` запрос на эндпоинт `/categories`. Вызывается при монтировании компонента и для обновления данных.
    *   **`handleDeleteCategory` (Delete):** Асинхронная функция для удаления категории. Показывает `window.confirm` для подтверждения действия. Отправляет `DELETE` запрос на `/categories/:id`. В случае успеха вызывает `fetchCategories` для обновления списка.
    *   **Create & Update:** Операции создания и обновления делегированы компоненту `CategoryForm`, но `CategoriesPage` управляет его открытием и передачей исходных данных.

*   **Обработчики событий:**
    *   `handleAddCategory`: Сбрасывает `selectedCategory` и открывает форму для создания новой категории.
    *   `handleEditCategory`: Устанавливает `selectedCategory` и открывает форму для редактирования.
    *   `handleFormClose`: Закрывает модальное окно формы.
    *   `handleFormSuccess`: Вызывается после успешного сохранения данных в форме, инициируя перезагрузку списка категорий.

*   **Контроль доступа:**
    *   Использует хук `usePermissions` для проверки прав.
    *   Кнопка "Добавить категорию" деактивирована, если у пользователя нет права `canEditResource('category')`.

*   **Визуальная структура (Layout):**
    *   Использует `Layout` для общего обрамления страницы.
    *   В верхней части (`Stack`) расположены заголовок и кнопки "Обновить" и "Добавить категорию".
    *   Основная область отображает либо индикатор загрузки, либо сообщение об ошибке, либо компонент `CategoryTable` со списком категорий. Если список пуст, выводится сообщение "Категории не найдены".

### 2.2. Компонент таблицы: `CategoryTable.tsx`

Отвечает за отображение списка категорий в табличном формате.

**Путь:** `frontend/coffecrm/components/Categories/CategoryTable.tsx`

**Ключевые особенности:**

*   **Представление данных:** Использует `TableContainer`, `Table`, `TableHead`, `TableBody` из Material-UI для создания структурированной и стилизованной таблицы.
*   **Колонки:**
    *   **Иконка:** Отображает `Avatar` с иконкой категории. Если URL иконки отсутствует, показывает `Avatar` с первой буквой названия категории.
    *   **Название:** Основное имя категории.
    *   **Дата создания:** Дата создания категории, отформатированная в локали `ru-RU`.
    *   **Действия:** Колонка с кнопками для редактирования и удаления.
*   **Контроль доступа:**
    *   Кнопки "Редактировать" (`EditIcon`) и "Удалить" (`DeleteIcon`) обернуты в `Tooltip` и становятся неактивными (`disabled`), если у пользователя нет соответствующих прав (`canEditResource`, `canDeleteResource`), проверяемых через хук `usePermissions`. Это предотвращает несанкционированные действия.
*   **Интерактивность:**
    *   При клике на кнопки "Редактировать" или "Удалить" вызываются функции `onEdit` и `onDelete`, переданные через `props` из родительского компонента `CategoriesPage`.

### 2.3. Компонент формы: `CategoryForm.tsx`

Модальное окно (`Dialog`) для создания и редактирования данных одной категории.

**Путь:** `frontend/coffecrm/components/Categories/CategoryForm.tsx`

**Режимы работы:**

*   **Создание (`isEdit = false`):** Когда `props.category` не передан. Заголовок — "Добавить категорию". Отправляет `POST` запрос на `/categories`.
*   **Редактирование (`isEdit = true`):** Когда `props.category` передан. Заголовок — "Редактировать категорию". Отправляет `PATCH` запрос на `/categories/:id`.

**Поля формы:**

*   **Название категории:** Обязательное текстовое поле.
*   **URL иконки:** Необязательное текстовое поле.
*   **Предпросмотр иконки:** Если URL иконки введен, под полем отображается `Avatar` для предпросмотра изображения.

**Логика работы:**

1.  При открытии форма заполняется данными из `props.category` (если они есть) или остается пустой.
2.  При отправке (`handleSubmit`) формируется `payload` с данными из полей формы.
3.  Определяется URL и HTTP-метод в зависимости от режима.
4.  Выполняется `fetch` запрос с аутентификацией.
5.  В случае успеха вызываются колбэки `onSuccess()` и `onClose()`.
6.  В случае ошибки выводится `alert`.
7.  Кнопка отправки и поля формы блокируются на время запроса (`loading: true`) или если у пользователя нет прав на редактирование (`!editable`).

## 3. Поток данных и взаимодействие с API

1.  **Загрузка:** Пользователь заходит на `/categories`. `CategoriesPage` отправляет `GET /categories`.
2.  **Отображение:** API возвращает список категорий. Данные сохраняются в `state` и передаются в `CategoryTable`, который отрисовывает строки таблицы.
3.  **Редактирование:**
    *   Пользователь нажимает иконку "Редактировать" в строке.
    *   `CategoryTable` вызывает `onEdit(category)`.
    *   `CategoriesPage` устанавливает `selectedCategory` и `formOpen = true`.
    *   `CategoryForm` открывается, заполненная данными из `selectedCategory`.
    *   Пользователь меняет данные и нажимает "Сохранить".
    *   `CategoryForm` отправляет `PATCH /categories/:id`.
    *   После успешного ответа `CategoryForm` вызывает `onSuccess()` и `onClose()`.
    *   `CategoriesPage` в `onSuccess()` вызывает `fetchCategories()`, обновляя список.
4.  **Удаление:**
    *   Пользователь нажимает иконку "Удалить".
    *   `CategoryTable` вызывает `onDelete(id)`.
    *   `CategoriesPage` показывает `window.confirm`.
    *   Если пользователь подтверждает, отправляется запрос `DELETE /categories/:id`.
    *   После успеха `fetchCategories()` обновляет список, и удаленная категория исчезает из таблицы.

## 4. Визуальный дизайн и UX

*   **Ясность и простота:** Интерфейс представляет собой классическую схему "список-детали" (в данном случае, "список-форма"), которая интуитивно понятна пользователям.
*   **Обратная связь:** Система активно использует индикаторы загрузки, всплывающие подсказки и диалоговые окна подтверждения, что делает взаимодействие с пользователем предсказуемым.
*   **Визуальная иерархия:** Использование `Paper` для `TableContainer`, `Avatar` для иконок и акцентных цветов для кнопок (`contained` для основной, `outlined` для второстепенной) создает четкую визуальную иерархию.
*   **Отказоустойчивость:** Обработка состояний загрузки и ошибок, а также гранулярное управление доступом к действиям, повышают надежность интерфейса.
