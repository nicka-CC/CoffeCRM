# CoffeCRM Страница "Склад" (inventory/page.tsx) - Подробное описание

## 1. Общее назначение

Страница "Склад" является критически важной операционной панелью для управления запасами ингредиентов и расходных материалов во всех филиалах. Ее основная цель — предоставить актуальное централизованное представление об уровнях запасов, отслеживать движение товаров и заблаговременно предупреждать менеджеров о товарах, заканчивающихся на складе. Это помогает предотвращать нехватку товаров, оптимизировать закупки и сокращать потери.

## 2. Структура страницы и компоненты

Страница спроектирована как двухколоночная панель, с приоритетом наиболее важной информации.

### 2.1. Заголовок и сводные чипы (Summary Chips)

-   **Заголовок**: "Склад".
-   **Сводные чипы**: Ряд компонентов `Chip` вверху предоставляет высокоуровневую сводку по всему инвентарю:
    -   **Общий запас (Total Stock)**: Сумма всех единиц всех товаров во всех локациях.
    -   **Оценочная стоимость (Estimated Value)**: Общая денежная стоимость всех запасов.
    -   **Зарезервировано (Reserved)**: Количество товаров, зарезервированных для открытых заказов или других обязательств.
    -   **Низкий запас (Low Stock)**: Количество уникальных товаров, уровень которых опустился ниже установленного минимального порога.
-   **Кнопка обновления (Refresh Button)**: Позволяет вручную перезагрузить все данные инвентаря.

### 2.2. Основной макет контента

Страница разделена на две основные колонки: большая таблица для детального обзора и меньшая боковая панель для срочных оповещений.

#### 2.2.1. Таблица запасов ингредиентов (левая колонка)

-   **Назначение**: Это ядро страницы, подробная таблица, перечисляющая каждый товар на складе в каждом филиале.
-   **Разворачиваемые строки (Expandable Rows)**: Ключевой особенностью является то, что каждая строка может быть развернута. Нажатие на иконку разворачивания открывает вложенную подтаблицу, показывающую **"Последние операции" (Recent Transactions)** для этого конкретного товара, предоставляя быстрый журнал аудита его движения.
-   **Колонки**:
    -   **Продукт (Product)**: Название, артикул (SKU) и изображение товара на складе.
    -   **Филиал (Branch)**: Филиал, где находится товар, включая его город и конкретное место хранения (если есть).
    -   **Количество (Quantity)**: Общее количество в наличии, с отдельно показанным зарезервированным количеством.
    -   **Доступно (Available)**: Фактически доступное количество (Общее - Зарезервировано). Это значение окрашено в красный цвет, если оно ниже минимального порога.
    -   **Стоимость (Value)**: Оценочная денежная стоимость запасов для этого товара.
    -   **Статус (Status)**: `Chip`, указывающий, является ли уровень запаса "Норма" (Normal) или "Низкий остаток" (Low Stock).
    -   **Действия (Actions)**: Кнопка-иконка "Зарегистрировать движение" (Register Transaction), которая открывает диалоговое окно `InventoryTransactionDialog`.
-   **Пагинация (Pagination)**: Таблица имеет пагинацию для обработки большого количества товаров на складе.

#### 2.2.2. Панель оповещений о низких запасах (правая колонка)

-   **Назначение**: Эта панель служит выделенным, высокоприоритетным списком "дел" для менеджеров по инвентаризации. Она изолирует только те товары, которые требуют немедленного внимания.
-   **Макет (Layout)**: Содержит серию компонентов `Card`, по одному для каждого оповещения о низком запасе.
-   **Карточка оповещения (Alert Card)**: Каждая карточка предоставляет краткое изложение проблемы:
    -   Название и изображение продукта.
    -   Название филиала и контактная информация менеджера.
    -   Четкое отображение `Остатка` (Remaining) против `Порога` (Threshold).

### 2.3. Диалоговое окно транзакции инвентаризации (`<InventoryTransactionDialog>`)

-   **Назначение**: Модальная форма для записи любого изменения количества на складе. Это основной механизм для поддержания точности данных инвентаризации.
-   **Типы транзакций (Transaction Types)**: Диалоговое окно позволяет пользователям регистрировать различные типы движений:
    -   **ПРИХОД (INCOME)**: Получение новой поставки от поставщика.
    -   **РАСХОД (EXPENSE)**: Использование ингредиентов для производства.
    -   **СПИСАНИЕ (WRITEOFF)**: Утилизация просроченных или поврежденных товаров.
-   **Поля (Fields)**: Содержит поля для `типа` транзакции, `количества`, `цены` (для отслеживания затрат), `причины` и связанного `номера документа`.

## 3. Поток данных и управление состоянием

-   **Параллельная выборка (Parallel Fetching)**: Функция `fetchData` использует `Promise.all` для выполнения двух одновременных вызовов API: один для основного обзора запасов и один специально для оповещений о низких запасах. Это улучшает производительность загрузки страницы.
-   **Состояние (State)**: Компонент управляет несколькими частями состояния:
    -   `overview`: Основной массив товаров на складе для таблицы.
    -   `alerts`: Отдельный массив для товаров на панели низких запасов.
    -   `dialogOpen` и `selectedStock`: Для управления диалоговым окном транзакций.
    -   `expandedRows`: Объект, который отслеживает, какие строки в таблице в данный момент развернуты (например, `{ 'stock-item-id-123': true }`).
    -   Состояние пагинации (`page`, `rowsPerPage`, `total`).
-   **Мемоизированные вычисления (Memoized Calculations)**: `useMemo` используется для эффективного расчета значений сводных чипов (`totalValue`, `totalQuantity` и т.д.) только при изменении данных `overview`.

## 4. Пользовательские сценарии

### 4.1. Ежедневная проверка инвентаря

1.  Менеджер открывает страницу "Склад".
2.  Сначала он просматривает панель "Оповещения о низких запасах" справа. Он видит, что "Кофейные зерна" в "Кафе на главной улице" заканчиваются.
3.  Затем он находит товар "Кофейные зерна" для этого филиала в основной таблице слева. Строка выделена желтым цветом, указывая на низкий запас.
4.  Он нажимает на иконку разворачивания в этой строке. Появляется подтаблица последних операций, показывающая, что большое количество было использовано вчера.
5.  Это побуждает его разместить новый заказ у поставщика.

### 4.2. Получение новой поставки

1.  В филиал поступает партия молока.
2.  Менеджер находит "Молоко" для своего филиала в таблице инвентаризации.
3.  Он нажимает кнопку-иконку "Зарегистрировать движение" в столбце действий.
4.  Открывается `InventoryTransactionDialog`.
5.  Он выбирает тип `ПРИХОД`, вводит полученное количество (например, 20 литров), цену за литр из счета и номер счета в поле "Документ".
6.  После сохранения вызывается функция `fetchData`, и таблица обновляется, показывая новое, большее количество молока. Статус "Низкий запас", если он был активен, теперь меняется обратно на "Норма".
