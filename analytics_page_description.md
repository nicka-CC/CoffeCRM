# Подробное описание страницы "Аналитика" (`/analytics`)

## 1. Введение

Страница "Аналитика" представляет собой мощный инструмент для глубокого анализа бизнес-показателей, превосходящий по своим возможностям базовый "Dashboard". Если "Dashboard" дает быстрый срез текущей ситуации, то страница "Аналитика" позволяет пользователям исследовать данные за различные периоды, выявлять закономерности и экспортировать детализированные отчеты для дальнейшего изучения или отчетности.

Эта страница является ключевой для принятия стратегических решений, основанных на данных. Она объединяет в себе несколько интерактивных отчетов, визуализированных с помощью графиков и диаграмм, и предоставляет функциональность для экспорта этих данных во внешние форматы.

## 2. Архитектура и расположение

-   **Путь в приложении:** `/analytics`
-   **Расположение файла:** `frontend/coffecrm/app/analytics/page.tsx`
-   **Технологический стек:** Аналогичен "Dashboard", с акцентом на более сложные визуализации данных.
    -   **Фреймворк:** Next.js (App Router)
    -   **Язык:** TypeScript
    -   **UI-библиотека:** Material-UI (MUI)
    -   **Библиотека для графиков:** Recharts

## 3. Поток данных (Data Flow)

1.  **Инициализация:** При загрузке страницы компонент устанавливает начальные состояния: `loading` в `true`, `period` в `'month'`, и пустые строки для кастомного диапазона дат (`from`, `to`).
2.  **Запрос данных:**
    *   `useEffect` отслеживает изменения в состояниях `period`, `from`, и `to` и вызывает функцию `fetchAnalytics`.
    *   Функция `fetchAnalytics` формирует URL для запроса к API. Она использует утилиту `buildUrl`, добавляя параметры:
        -   `period`: `week`, `month`, `quarter`, или `custom`.
        -   `from`, `to`: добавляются, только если `period` равен `'custom'`.
    *   Пример URL: `/api/analytics?period=month` или `/api/analytics?period=custom&from=2023-01-01&to=2023-01-31`.
    *   Отправляется GET-запрос с заголовками авторизации.
3.  **Обработка ответа:**
    *   **Успех:** JSON ответа сохраняется в состояние `analyticsData`, `loading` становится `false`, `error` обнуляется. Компонент перерисовывается с новыми данными.
    *   **Ошибка:** Сообщение об ошибке сохраняется в состояние `error`, `loading` становится `false`. UI отображает `<Alert>`.
4.  **Экспорт данных:**
    *   Функция `handleExport` вызывается при выборе соответствующей опции из меню экспорта.
    *   Она принимает два аргумента: `dataset` (какой отчет нужен) и `format` (`excel` или `pdf`).
    *   Формируется URL для эндпоинта экспорта: `/api/analytics/export?dataset=sales&format=pdf&...`.
    *   Отправляется запрос, и в ответ ожидается `blob` (бинарные данные файла).
    *   С помощью `window.URL.createObjectURL(blob)` создается временная ссылка.
    *   Программно создается тег `<a>`, ему присваивается эта ссылка и атрибут `download` с динамически сгенерированным именем файла (например, `отчет-продажи-15-03-2026-10-30.pdf`).
    *   Эмулируется клик по ссылке, что инициирует скачивание файла браузером.

**Структура получаемых данных (`analyticsData`):**

```typescript
interface AnalyticsData {
  salesDynamics: {
    date: string;       // Дата
    orders: number;     // Количество заказов
    revenue: number;    // Выручка
  }[];
  topCustomers: {
    customerId: string;
    name: string | null;
    phone: string | null;
    revenue: string; // Приходит как строка, приводится к числу
  }[];
  branchSales: {
    name: string;       // Название филиала
    revenue: string; // Приходит как строка, приводится к числу
  }[];
  peakHours: {
    hour: number;       // Час (0-23)
    orders: number;     // Количество заказов
  }[];
  topProducts: any[]; // В коде есть, но в UI не используется
}
```

## 4. Детальный разбор UI-компонентов

### 4.1. Панель управления (Header & Filters)

-   **Заголовок и кнопки действий:**
    -   **"Обновить":** `Button` с иконкой `RefreshIcon`, по клику вызывает `fetchAnalytics` для перезагрузки данных.
    -   **"Экспорт отчета":** `Select`, стилизованный под кнопку. При выборе опции (например, "Отчет по продажам (Excel)") вызывается `handleExport` с соответствующими параметрами. Меню экспорта сгруппировано по форматам (Excel, PDF) с помощью `ListSubheader`.
-   **Панель фильтров:**
    -   **"Период":** `Select` для выбора одного из предустановленных периодов: "Неделя", "Месяц", "Квартал", "Произвольный".
    -   **Кастомные даты:** Если выбран период "Произвольный", появляются два поля `TextField` с `type="date"` для выбора начальной (`from`) и конечной (`to`) дат.

### 4.2. Виджет "Динамика продаж"

-   **Компонент:** `LineChart` из Recharts.
-   **Назначение:** Показывает изменение количества заказов и выручки с течением времени.
-   **Особенности:**
    -   **Две оси Y:** `YAxis yAxisId="left"` для количества заказов и `YAxis yAxisId="right"` для выручки. Это позволяет корректно отображать две метрики с разными масштабами на одном графике.
    -   **Линии:** Две сглаженные (`type="monotone"`) линии: одна для `orders` (фиолетовая), другая для `revenue` (зеленая).
    -   **Кастомный Tooltip:** `RechartsTooltip` использует `formatter` для форматирования значения выручки, добавляя знак валюты с помощью `formatCurrency()`.

### 4.3. Виджет "ТОП клиентов"

-   **Компонент:** Горизонтальный `BarChart` из Recharts (`layout="vertical"`).
-   **Назначение:** Ранжирует клиентов по общей сумме покупок (выручке).
-   **Особенности:**
    -   **Оси:** Ось Y (`YAxis`) категориальная, отображает имена клиентов. Ось X (`XAxis`) числовая, показывает сумму выручки.
    -   **Имена клиентов:** В коде предусмотрена логика для отображения имени: если есть `name`, используется оно; если нет, то `phone`; если и его нет, то усеченный `customerId`.
    -   **Цвета:** Цвета для столбиков (`Bar`) циклически берутся из массива `COLORS`, что делает график визуально разнообразным.
    -   **Быстрый экспорт:** В заголовке виджета есть иконка `GridOnIcon` для быстрого экспорта именно этого отчета в Excel.

### 4.4. Виджет "Продажи по филиалам"

-   **Компонент:** `PieChart` из Recharts.
-   **Назначение:** Показывает долю выручки каждого филиала в общей сумме.
-   **Особенности:**
    -   **Кольцевая диаграмма:** Задается с помощью `innerRadius`, что создает "дырку" в центре, превращая круговую диаграмму в кольцевую.
    -   **Метки:** Метки (`label`) отображаются прямо на сегментах диаграммы и показывают название филиала и его долю в процентах.
    -   **Легенда:** Расположена справа от графика (`align="right"`), также показывает процентную долю каждого филиала.
    -   **Кастомный Tooltip:** При наведении на сегмент показывает точное значение выручки, отформатированное `formatCurrency()`.
    -   **Быстрый экспорт:** Аналогично "ТОП клиентам", есть иконка для экспорта отчета по филиалам в Excel.

### 4.5. Виджет "Пиковые часы заказов"

-   **Компонент:** `BarChart` из Recharts.
-   **Назначение:** Визуализирует распределение количества заказов по часам в сутках, помогая определить часы наибольшей нагрузки.
-   **Особенности:**
    -   **Данные:** График всегда рендерит 24 столбика (для каждого часа), даже если для какого-то часа нет данных (в этом случае количество заказов равно 0).
    -   **Выделение пиковых часов:** Столбики, соответствующие "пиковым" часам (с 10 до 14 и с 18 до 21), окрашиваются в более насыщенный цвет (`#8b5cf6`), а остальные — в более светлый (`#c4b5fd`). Эта логика зашита прямо в рендеринг компонента `Cell` внутри `Bar`.
    -   **Подсказка:** Под графиком есть текстовая подсказка, объясняющая цветовую кодировку.
