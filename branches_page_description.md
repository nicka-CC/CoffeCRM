# Описание страницы "Филиалы" (`/branches`)

## 1. Обзор и назначение

Страница "Филиалы" является центральным узлом для управления и мониторинга всей сети кофеен. Она предоставляет администраторам и менеджерам полный набор инструментов для визуализации географического расположения филиалов, анализа их ключевых показателей эффективности (KPI) и выполнения основных CRUD-операций (создание, чтение, обновление, удаление).

**Ключевые цели страницы:**

*   **Географическая визуализация:** Наглядно представить расположение всех филиалов на интерактивной карте, включая центральный склад, и предоставить возможность построения логистических маршрутов.
*   **Операционный контроль:** Обеспечить быстрый доступ к списку всех филиалов с их контактной информацией и основными статистическими данными.
*   **Аналитика и производительность:** Показать ключевые метрики для каждого филиала, такие как выручка, количество заказов, численность персонала и остатки на складе, для быстрого анализа и принятия решений.
*   **Управление данными:** Предоставить авторизованным пользователям возможность добавлять новые филиалы и (подразумеваемо, через страницу деталей) редактировать или удалять существующие.

Страница спроектирована как гибридная панель, сочетающая в себе геоинформационную систему (ГИС) и классический табличный/карточный интерфейс для всестороннего обзора и управления сетью.

## 2. Структура и компоненты

Страница построена на модульной архитектуре с использованием нескольких ключевых React-компонентов, каждый из которых отвечает за свою часть функциональности.

### 2.1. Основной компонент: `BranchesPage.tsx`

Это корневой компонент страницы, который оркестрирует взаимодействие всех остальных элементов.

**Путь:** `frontend/coffecrm/app/branches/page.tsx`

**Ключевые обязанности:**

*   **Состояние (State Management):**
    *   `branches: BranchSummary[]`: Массив объектов, содержащий информацию о всех филиалах. Загружается из API.
    *   `loading: boolean`: Флаг, указывающий на процесс загрузки данных. Используется для отображения индикатора загрузки (`CircularProgress`).
    *   `error: string | null`: Хранит сообщение об ошибке, если загрузка данных не удалась. Используется для отображения компонента `Alert`.
    *   `formOpen: boolean`: Управляет видимостью модального окна `BranchForm` для создания нового филиала.
    *   `selectedBranchId: number | null`: Хранит ID филиала, выбранного на карте или в других компонентах, для синхронизации состояния между ними.

*   **Жизненный цикл и загрузка данных:**
    *   При монтировании компонента (`useEffect`) запускается асинхронная функция `fetchBranches`.
    *   Эта функция отправляет `GET` запрос на эндпоинт `${API_BASE_URL}/branches?withStats=true`. Параметр `withStats=true` указывает бэкенду на необходимость включить в ответ статистические данные по каждому филиалу.
    *   Запрос использует `withAuthHeaders` для добавления необходимых заголовков аутентификации.
    *   В случае успешного ответа данные нормализуются и сохраняются в состоянии `branches`. Особое внимание уделяется обработке `null` значений для полей `phone`, `email`, `latitude`, `longitude` и `stats`.
    *   В случае ошибки выводится сообщение в консоль и устанавливается состояние `error`.
    *   Функция `refetch` выполняет те же действия и вызывается после успешного создания нового филиала для обновления списка.

*   **Контроль доступа (Permissions):**
    *   Используется кастомный хук `usePermissions`.
    *   Кнопка "Создать филиал" отображается только в том случае, если `perms.canEditResource('branch')` возвращает `true`. Это обеспечивает гранулярный контроль доступа к созданию новых сущностей.

*   **Визуальная структура (Layout):**
    *   Оборачивает все содержимое в компонент `Layout`, передавая ему заголовок "Филиалы" и подзаголовок.
    *   Содержит два основных блока:
        1.  **Секция карты:** Отображает компонент `BranchesMap`.
        2.  **Секция списка филиалов:** Отображает заголовок, кнопку "Создать филиал" и сетку (`Grid`) с компонентами `BranchCard`.

### 2.2. Компонент карты: `BranchesMap.tsx`

Этот компонент отвечает за всю интерактивность, связанную с картой.

**Путь:** `frontend/coffecrm/components/Branches/BranchesMap.tsx`

**Ключевые особенности:**

*   **Технология:** Интеграция с **Yandex Maps API 2.1**. Скрипт API загружается асинхронно при первом рендере компонента, чтобы не блокировать загрузку страницы.
*   **Объекты на карте:**
    *   **Центральный склад (`WAREHOUSE_NAME`):** Статичная метка (`Placemark`) красного цвета.
    *   **Филиалы:** Метки синего цвета, созданные на основе координат из `props.branches`. Отображаются только филиалы, у которых заданы `latitude` и `longitude`.
*   **Интерактивность:**
    *   **Выбор филиала:** Пользователь может выбрать филиал, кликнув на его метку на карте или выбрав его из выпадающего списка.
    *   **Подсветка и центрирование:** Выбранный филиал подсвечивается (стиль метки меняется на `islands#blueStretchyIcon`) и карта плавно центрируется на нем.
    *   **Построение маршрута:** При выборе филиала из выпадающего списка строится и отображается автомобильный маршрут от этого филиала до центрального склада.
    *   **Масштабирование:** Карта автоматически масштабируется, чтобы показать все филиалы при первоначальной загрузке и чтобы полностью вместить построенный маршрут.
*   **Управление состоянием:**
    *   Компонент может работать в двух режимах: управляемом (через `props.selectedBranchId` и `props.onBranchSelect`) и неуправляемом (используя собственное состояние `localSelectedId`). Это делает его гибким и переиспользуемым.
*   **UI элементы:**
    *   **Выпадающий список (`Select`):** Расположен вверху карты и позволяет пользователю выбрать филиал для построения маршрута.
    *   **Кнопка "Очистить маршрут":** Появляется под выпадающим списком после построения маршрута.
    *   **Всплывающие подсказки (`hintContent`, `balloonContent`):** При наведении на метку отображается название филиала, а при клике — более подробная информация.

### 2.3. Компонент карточки филиала: `BranchCard.tsx`

Представляет собой компактное "досье" на каждый филиал в списке.

**Путь:** `frontend/coffecrm/components/Branches/BranchCard.tsx`

**Отображаемая информация:**

*   **Идентификация:** Название, город и адрес.
*   **Контакты:** Телефон и email (отображаются, только если они есть).
*   **Статистика (`stats`):**
    *   `revenue`: Выручка, форматированная с помощью `formatCurrency`.
    *   `orders`: Общее количество заказов.
    *   `employees`: Количество сотрудников.
    *   `stockQuantity`: Общее количество товаров на складе.
    *   Каждый показатель отображается в виде `Chip` с иконкой для лучшего визуального восприятия.

*   **Навигация:**
    *   **Чип "Подробнее" и иконка:** Являются ссылками (`Link`) на страницу деталей филиала (`/branches/${branch.id}`), где, предположительно, можно будет увидеть более подробную информацию и выполнить операции редактирования или удаления.

### 2.4. Компонент формы: `BranchForm.tsx`

Модальное окно для создания и редактирования филиалов.

**Путь:** `frontend/coffecrm/components/Branches/BranchForm.tsx`

**Режимы работы:**

*   **Создание:** Активируется, когда `props.initial` не передан. Отправляет `POST` запрос на `/branches`.
*   **Редактирование:** Активируется, когда в `props.initial` переданы данные существующего филиала. Отправляет `PATCH` запрос на `/branches/:id`.

**Поля формы:**

*   Название (обязательное)
*   Город (обязательное)
*   Адрес (обязательное)
*   Телефон (опциональное)
*   Email (опциональное)
*   Широта (опциональное, для отображения на карте)
*   Долгота (опциональное, для отображения на карте)

**Процесс отправки:**

1.  Пользователь нажимает кнопку "Создать" или "Сохранить".
2.  Запускается `handleSubmit`, который предотвращает стандартное поведение формы.
3.  Собирается объект `payload` с данными из формы. Пустые опциональные поля не включаются. Координаты преобразуются в `float`.
4.  Выбирается URL и HTTP-метод в зависимости от режима (создание/редактирование).
5.  Выполняется `fetch` запрос с аутентификацией и телом в формате JSON.
6.  В случае успеха вызываются колбэки `onSuccess()` (для обновления данных на главной странице) и `onClose()` (для закрытия окна).
7.  В случае ошибки выводится `alert` с сообщением.
8.  На время запроса кнопка отправки блокируется (`loading: true`).

**Контроль доступа:**

*   Кнопка отправки (`submit`) заблокирована (`disabled`), если у пользователя нет соответствующих прав (`canCreateResource` или `canEditResource`).

## 3. Поток данных и взаимодействие с API

1.  **Загрузка страницы:** Пользователь переходит на `/branches`.
2.  **Первичная загрузка данных:** `BranchesPage` запрашивает список филиалов с статистикой (`GET /branches?withStats=true`).
3.  **Отрисовка:**
    *   Пока идет загрузка, отображается `CircularProgress`.
    *   После загрузки данные передаются в `BranchesMap` и `BranchCard`.
    *   `BranchesMap` отрисовывает метки на карте.
    *   `BranchesPage` в цикле `.map` отрисовывает компоненты `BranchCard` для каждого филиала.
4.  **Создание нового филиала:**
    *   Пользователь с правами нажимает "Создать филиал".
    *   `BranchesPage` устанавливает `formOpen = true`.
    *   Открывается модальное окно `BranchForm`.
    *   Пользователь заполняет форму и нажимает "Создать".
    *   `BranchForm` отправляет `POST` запрос на `/branches` с данными формы.
    *   В случае успеха API возвращает созданный объект.
    *   `BranchForm` вызывает `onSuccess()` и `onClose()`.
    *   `BranchesPage` получает вызов `onSuccess`, который запускает `refetch()`.
    *   `refetch()` заново запрашивает данные с `GET /branches?withStats=true`.
    *   Состояние `branches` обновляется, и на странице появляется новый филиал.
5.  **Взаимодействие с картой:**
    *   Пользователь выбирает филиал в выпадающем списке на карте.
    *   `BranchesMap` обновляет свое состояние (или вызывает `onBranchSelect`).
    *   `BranchesMap` отправляет запрос в Yandex Maps API для построения маршрута.
    *   API возвращает геометрию маршрута, которая отрисовывается на карте.

## 4. Визуальный дизайн и UX

*   **Консистентность:** Страница использует компоненты из библиотеки Material-UI (`@mui/material`), что обеспечивает единый и привычный для пользователя внешний вид.
*   **Информативность:** Ключевая информация, такая как статистика, выделена с помощью чипов (`Chip`) разных цветов и иконок, что позволяет быстро считывать состояние дел.
*   **Интерактивность:** Плавные анимации карты, подсветка выбранных элементов и мгновенная обратная связь (индикаторы загрузки, сообщения об ошибках) делают интерфейс отзывчивым и удобным.
*   **Адаптивность:** Использование `Grid` компонента от MUI позволяет карточкам филиалов корректно перестраиваться на разных размерах экрана.
*   **Прогрессивное раскрытие:** Основная информация видна сразу, а детали (например, форма создания или подробная страница филиала) доступны по клику, что не перегружает основной интерфейс.
